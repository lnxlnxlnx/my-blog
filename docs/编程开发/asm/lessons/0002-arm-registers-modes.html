A02 · Cortex-A7 寄存器组与处理器模式

汇编课 · 阅读约 15 分钟

A01 里 r0、r1、"SP" 都是什么？为什么中断要分身？这课把 ARM CPU 的"储物柜"和"工作模式"讲清楚——它是读懂所有汇编和 u-boot/Kernel 汇编代码的前提。

通用寄存器：16 个小柜子（r0~r15）

ARM 处理器有 16 个通用寄存器，其中几个还有特殊职责（对照《指南》第 6 章）：

寄存器别名职责
r0 ~ r7—纯通用：装数据、算数
r8 ~ r12—通用（r8-r12 在 FIQ 模式有备份，先记住名字）
r13SP（栈指针）指向当前栈顶；压栈/弹栈都动它
r14LR（链接寄存器）调用子程序 bl 时，存"返回地址"
r15PC（程序计数器）当前正在执行的指令地址（ARM 中等于当前指令+8）

再加一个状态寄存器 CPSR：存条件标志（Z/N/C/V）、中断使能位、当前处理器模式位。条件跳转（beq/bne）就看它的标志。

处理器模式：一个 CPU 的多种"工牌"

Cortex-A7 有好几种模式，区别就像员工临时切换工牌，权利不同、专用寄存器也不同：

模式用途
User（USR）正常用户程序（受限：不能直接改 CPSR 和很多寄存器）
System（SYS）和 User 同寄存器，但特权级更高，常用于驱动/裸机入口代码
Supervisor（SVC）操作系统内核（通过软中断 SWI 进入）；裸机 main 常跑在 SVC
IRQ / FIQ中断处理（硬件中断进来自动切到它，有独立的 SP/LR，避免打断工作现场）
Abort（ABT）/ Undefined（UND）异常/未定义指令

为什么要有模式？最朴素的理由：中断来时要有"独立的工作现场"（独立的 SP/LR），才不会把正在干的活搞乱。你在 Linux 驱动课 L06 学中断时，内核会自动帮你切到 IRQ 模式。

你已经在用"模式"了

A01 里 b loop、ldr r0,= 都在某个模式下执行。裸机入口 _start 一般在 SVC 模式（上电/复位后就是 SVC）。给你一个观察点：u-boot 和 Linux 内核的入口汇编也是这么开头（设置各模式 SP、切模式、跳 C 入口）。

练习 A02：只读、联想

  2. 如果我把 r1 换成 r13（SP）写值，会不会出问题？为什么？（提示：SP 有专门用途，乱动会让栈崩）
  3. 在你的板子的 u-boot 里 printenv/反汇编联想：等 L13 学 u-boot 时，你会看到它对每种模式各设一个 SP——现在埋下印象。
自测
bl 调用子程序时，返回地址存哪个寄存器？

LR（r14）。bl 先把下一条指令地址放入 LR，再跳去执行子程序。子程序末尾把 LR 回传（或压栈恢复）就能"回来"。

SP 是干嘛的？乱改它为什么危险？

SP 指向栈顶，压栈(push)和弹栈(pop)都靠它。乱改成非法值会让 push/pop 写到错误内存 → 栈破坏、函数返回就崩。

为什么要分 IRQ 模式？好处是？

中断处理切换到 IRQ 模式，有自己独立的 SP/LR，不污染被打断任务的工作现场。中断处理完切回原模式，恢复原现场，正常继续。

要带走的 ① r0-r15 + SP/LR/PC + CPSR 的角色；② 模式 = 独立现场 + 特权分级；③ 你已在 SVC/IRQ 模式里"生活"过了。下一课把"统一词汇表"变成能写代码的指令。
