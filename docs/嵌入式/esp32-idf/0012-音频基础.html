音频基础：I2S / Codec / Opus

ESP-IDF 课程 · 课程 0012 · 预计 20 分钟

xiaozhi 是语音设备,它的音频流水线占了固件一大半。这一课给你三个概念地图:I2S(数字音频总线)、Codec 芯片(模拟↔数字)、Opus(网络音频编码)。不要求你写音频代码,但读 xiaozhi 的 audio/ 目录必须认识它们。

知识点 1:I2S——音频数据的公路

麦克风/喇叭是模拟信号,CPU 是数字世界,中间的桥梁是 Codec 芯片,而 Codec 和 CPU 之间走 I2S(数字音频串行总线):

Mic(模拟) → Codec ADC → I2S → CPU(录音)
CPU(播放) → I2S → Codec DAC → Speaker(模拟)

IDF 里有 i2s_std_init(新 driver)或老 i2s_driver_install。采样率 16k/24k/48k、位数 16/24/32 都在配置里定。

知识点 2:Opus——网络语音编码

设备和服务器的音频走网络,用 Opus 编码(高压缩、低延迟、语音/音乐通吃)。xiaozhi 协议里每 60ms 一帧 Opus,设备收到就解码播放:

esp_opus_decoder_create(24000, 1, &dec);  // 24kHz 单声道
esp_opus_decode(dec, opus_pkt, len, pcm, &out_len);

这就是为什么服务器端音乐要先转成 24k 单声道——和设备协商一致才不卡(还记得咱们改的 WAV 缓存吗)。

知识点 3:回声消除与唤醒(AFE)

音箱要"听到自己说的话又认出唤醒词",需要 AFE(音频前端):回声消除(AEC)、降噪(NS)、唤醒词检测。乐鑫的 esp-sr 组件提供这些——xiaozhi 的 audio/ 里就是 AFE 的封装。

动手

打开 basic_routines/30_music 和 31_recoding:确认音频走 I2S 还是 I2S 模拟,采样率多少。然后浏览 xiaozhi-esp32-2.2.4/main/audio/ 目录,把文件名列下来——下一课逐个讲。

小测验

Q1

CPU 和 Codec 之间走什么总线?

I2S,数字音频专用串行总线。

Q2

xiaozhi 与服务器之间音频用什么编码?

Opus,60ms 一帧,低延迟高压缩。
