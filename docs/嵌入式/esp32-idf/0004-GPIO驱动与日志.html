GPIO 驱动与日志

ESP-IDF 课程 · 课程 0004 · 预计 15 分钟

STM32 的 HAL_GPIO_Init/WritePin/ReadPin 你在行。IDF 的 GPIO 风格完全不同——先配置后使用,配置靠结构体,函数是 gpio_ 前缀的平铺 API。这一课翻译到位,顺便学会 ESP32 的看家日志 ESP_LOGx。

知识点 1:配置即结构体

// STM32:GPIO_InitTypeDef + HAL_GPIO_Init(GPIOB, &cfg);
// ESP32:同样"填结构体",但函数是 gpio_config()
gpio_config_t io = {
    .pin_bit_mask = 1ULL << GPIO_NUM_2,  // 注意是位掩码
    .mode = GPIO_MODE_OUTPUT,
    .pull_up_en = GPIO_PULLUP_DISABLE,
    .pull_down_en = GPIO_PULLDOWN_DISABLE,
    .intr_type = GPIO_INTR_DISABLE,
};
gpio_config(&io);
gpio_set_level(GPIO_NUM_2, 1);      // 输出高
gpio_set_level(GPIO_NUM_2, 0);      // 输出低

对照记忆:HAL 的 Init/WritePin/ReadPin ↔ IDF 的 gpio_config / gpio_set_level / gpio_get_level。每个外设(driver 组件)都是这个套路:xxx_config / xxx_init / xxx_读写。

知识点 2:日志系统(看代码第一工具)

#include "esp_log.h"
static const char *TAG = "my_app";
ESP_LOGE(TAG, "错误: %d", err);   // 错误(红)
ESP_LOGW(TAG, "警告");            // 警告
ESP_LOGI(TAG, "信息");             // 普通
ESP_LOGD(TAG, "调试(需开日志级别)");

idf.py monitor 打开的就是这个日志流。读开源代码第一件事:找 TAG,跟着 ESP_LOG 看执行流——xiaozhi 里到处是 ESP_LOGI(TAG,...)。

知识点 3:改日志级别

idf.py menuconfig
# Component config → Log output → 默认级别调到 DEBUG,能看到 ESP_LOGD

动手

回 basic_routines/00_basic/main/main.c,把上一课留的作业对答案:GPIO 初始化、延时、日志三个 API 分别是 gpio_config、vTaskDelay、ESP_LOGx。然后在代码里加一行 ESP_LOGI,idf.py -p /dev/ttyUSB0 flash monitor 看输出。

小测验

Q1

gpio_config 里 .pin_bit_mask 填什么?

1ULL << 引脚号,一次可配置多脚。

Q2

读陌生工程代码,最先跟着什么走?

ESP_LOGx,日志是执行流的索引。
