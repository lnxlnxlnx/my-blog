第 9 课：MiniOS③ 调度器与临界区

⭐ 手写内核第三步：OSSched、任务创建与第一个可运行的多任务 MiniOS

本课目标：第 8 课切换链路全自动、选人手动；本课把最后一块拼图装上：OS_SchedNew 填真算法、OSSched 成为统一调度入口、OSTaskCreate 让任务"出生即就绪"、BASEPRI 临界区落地，再配一个最低优先级的空闲任务兜底。学完你将拥有第一个真正全自动运行的多任务 MiniOS：两个任务轮流打印，抢占、让出、挂起/恢复全部自动完成。对照 µC/OS-III 的 OSSched（PDF p.133~136），你会发现我们的实现是它的骨架级简化。

1. 调度点设计：什么时候该问"换不换人"

µC/OS-III 的自动切换触发条件（PDF p.132 表 8.2.1）有一长串：发信号、延时、等事件、挂起/恢复、创建/删除任务、中断嵌套结束、解锁调度器……归拢起来就一句话——一切"就绪集合可能变化"的时刻。MiniOS 初版挑出四个调度点：

调度点触发动作谁调用 OSSchedUCOS 对应（表 8.2.1）
任务主动让出挂起自己OS_TaskSuspend（挂起的是当前任务时）OSTaskSuspend 挂起自身
任务被恢复恢复对方OS_TaskResumeOSTaskResume 恢复任务
新任务诞生创建任务OSTaskCreate（内核运行中时）任务被创建
延时到期时基节拍OSIntExit（下一课加入）中断嵌套结束

设计原则（本课反复强调）：OSSched 只管"问"——它检查就绪表，如果最高优先级任务不是当前任务就请求切换；绝不自己判断"该不该在此时调度"，那是各调用点的职责。µC/OS-III 原版的 OSSched 也是这样：一进来先过四道闸门。

2. OSSched()：四道闸门 + 一次选择

µC/OS-III 的 OSSched 源码（PDF p.133~136）结构如下，我们按骨架复刻：

/* ---------- MiniOS/os_sched.c：调度器（第 9 课交付） ---------- */
#include "os_core.h"
#include "cpu.h"

/* 第 8 课的空壳转正：从位图里取最高优先级，映射到 TCB 池槽位。
 * 由 PendSV 汇编调用（此时在 Handler 模式，用 MSP，任务栈不受影响） */
void  OS_SchedNew (void)
{
    OSPrioHighRdy   = OS_PrioGetHighest();
    OSTCBHighRdyPtr = &OSTCBTbl[OSPrioHighRdy];
}

/* 统一调度入口：任务级代码使用 */
void  OSSched (void)
{
    CPU_SR_ALLOC();

    if (OSRunning != OS_STATE_OS_RUNNING) {      /* 闸门①：内核没启动？ */
        return;
    }
    if (OSIntNestingCtr > 0u) {                  /* 闸门②：在中断里？中断用 OSIntExit 调度 */
        return;
    }
    if (OSSchedLockNestingCtr > 0u) {            /* 闸门③：调度器被锁？解锁时再补调 */
        return;
    }

    CPU_CRITICAL_ENTER();                        /* ④ 进临界区：保护"查表+比较"不被中断插队 */
    OSPrioHighRdy   = OS_PrioGetHighest();       /* ⑤ 查位图：最高就绪优先级（第 7 课，O(1)） */
    OSTCBHighRdyPtr = &OSTCBTbl[OSPrioHighRdy];

    if (OSTCBHighRdyPtr == OSTCBCurPtr) {        /* ⑥ 还是自己？不用切，直接回 */
        CPU_CRITICAL_EXIT();
        return;
    }

    OS_TASK_SW();                                /* ⑦ 挂起 PendSV（此刻中断仍被屏蔽） */
    CPU_CRITICAL_EXIT();                         /* ⑧ 出临界区 → BASEPRI=0 → PendSV 立即执行 */
}

对照教材源码的四个要点：

  • 闸门②的语义：中断里就绪集合变了，由 OSIntExit（第 6 课讲过）负责在"最外层中断退出"时调度——任务代码里的 OSSched 不该、也不能在中断里跑。
  • 闸门③的语义：调度器被锁（OSSchedLock）期间，任何调度请求都被记账"悬空"，解锁到最外层时由 OSSchedUnlock 补一次调度——这就是第 6 课"锁定调度器代替关中断"的完整闭环。
  • ⑦⑧的顺序：先挂起 PendSV、再出临界区。PendSV 挂起后因为优先级最低（第 6 课配的 0xFF），要等当前临界区出去、中断全部安静才执行——"换人区"永远在最后，这正是切换不被打断的底气。
  • 为什么查表要进临界区：OS_PrioGetHighest 读位图是"读-算-读"多条指令，若中间被 SysTick 插队改了位图，可能读到半新半旧的状态。临界区只保护这几条指令，纳秒级。

3. 临界区落地：cpu.h 的 BASEPRI 三件套

第 6 课讲透了原理（宏链一路展开到 BASEPRI），本课把它落进 MiniOS（cpu.h + os_cpu_a.asm）：

/* ---------- MiniOS/cpu.h（第 9 课补全版） ---------- */
#ifndef  CPU_H
#define  CPU_H

typedef  unsigned int    CPU_INT32U;
typedef  CPU_INT32U      CPU_DATA;      /* 32 位机器：字 */
typedef  CPU_INT32U      CPU_STK;       /* 栈单元：32 位 */
typedef  CPU_INT32U      CPU_SR;        /* 保存中断状态的变量类型 */
typedef  void          (*OS_TASK_PTR)(void *p_arg);
typedef  unsigned int    CPU_STK_SIZE;

/* ---------- 中断配置（对应第 6 课：受管理中断 = 优先级 4~15） ---------- */
#define  CPU_CFG_NVIC_PRIO_BITS   4u
#define  CPU_CFG_KA_IPL_BOUNDARY  4u

/* ---------- 临界区三件套（宏链终点是 os_cpu_a.asm 的 CPU_SR_Save/Restore） ---------- */
#define  CPU_SR_ALLOC()           CPU_SR  cpu_sr = (CPU_SR)0
#define  CPU_CRITICAL_ENTER()     do { cpu_sr = CPU_SR_Save( \
        CPU_CFG_KA_IPL_BOUNDARY << (8u - CPU_CFG_NVIC_PRIO_BITS)); } while (0)
#define  CPU_CRITICAL_EXIT()      do { CPU_SR_Restore(cpu_sr); } while (0)

CPU_SR  CPU_SR_Save    (CPU_SR new_basepri);   /* 汇编实现，os_cpu_a.asm */
void    CPU_SR_Restore (CPU_SR basepri);       /* 汇编实现，os_cpu_a.asm */

#endif
; ---------- MiniOS/os_cpu_a.asm：临界区汇编（第 6 课 4. 节已拆解，直接搬入） ----------
CPU_SR_Save
    CPSID   I
    PUSH   {R1}
    MRS    R1, BASEPRI        ; 读旧值
    MSR    BASEPRI, R0        ; 设新阈值（0x40：屏蔽优先级 4~15）
    DSB
    ISB
    MOV    R0, R1             ; 返回旧值
    POP    {R1}
    CPSIE  I
    BX     LR

CPU_SR_Restore
    CPSID   I
    MSR    BASEPRI, R0        ; 恢复进入临界区前的阈值
    DSB
    ISB
    CPSIE  I
    BX     LR

💡 至此第 6 课的"宏链"知识全部闭环：CPU_CRITICAL_ENTER() → CPU_SR_Save(0x40) → 汇编设 BASEPRI。MiniOS 里临界区的每一次进出，都意味着"中断禁用时间只有十几条指令"——这就是 µC/OS-III 风格的实时性保障，我们亲手实现了它。

4. OSTaskCreate：任务"出生即就绪"

µC/OS-III 的 OSTaskCreate 形参多达 13 个（PDF p.91~93），MiniOS 砍到 7 个，但内部五步不变：参数检查 → 填 TCB → 初始化任务栈 → 插入就绪表 → 运行中则调度（PDF p.119~127）：

/* ---------- MiniOS/os_task.c：任务创建与挂起/恢复（第 9 课交付） ---------- */
void  OSTaskCreate (OS_TCB       *p_tcb,
                    OS_TASK_PTR   p_task,
                    void         *p_arg,
                    OS_PRIO       prio,
                    CPU_STK      *p_stk_base,
                    CPU_STK_SIZE  stk_size,
                    OS_ERR       *p_err)
{
    CPU_SR_ALLOC();

    /* ① 参数检查（对照 UCOS 的 OS_ERR_XXX 错误码，PDF p.92~93） */
    if (p_tcb == (OS_TCB *)0)        { *p_err = OS_ERR_TCB_INVALID;   return; }
    if (p_task == (OS_TASK_PTR)0)    { *p_err = OS_ERR_TASK_INVALID;  return; }
    if (prio >= (OS_CFG_PRIO_MAX - 1u)) { *p_err = OS_ERR_PRIO_INVALID; return; }  /* 31 号留给空闲任务 */

    /* ② 填 TCB（UCOS 用 OS_TaskInitTCB()，PDF p.121） */
    p_tcb->Prio         = prio;
    p_tcb->TaskState    = OS_TASK_STATE_RDY;
    p_tcb->TickRemain   = 0u;
    p_tcb->TaskEntryArg = p_arg;

    /* ③ 初始化任务栈（第 8 课），栈顶存入 TCB 第一个成员 */
    p_tcb->StkPtr = OSTaskStkInit(p_task, p_arg, p_stk_base, stk_size);

    /* ④ 插入就绪位图（UCOS：OS_PrioInsert + OS_RdyListInsertTail，PDF p.126） */
    CPU_CRITICAL_ENTER();
    OS_PrioInsert(prio);
    CPU_CRITICAL_EXIT();

    *p_err = OS_ERR_NONE;

    /* ⑤ 内核已运行时，新任务可能更高优先级 → 立即调度 */
    if (OSRunning == OS_STATE_OS_RUNNING) {
        OSSched();
    }
}

/* 挂起任务：移出就绪表；挂起自己必须立即让出 CPU */
void  OS_TaskSuspend (OS_TCB *p_tcb)
{
    CPU_SR_ALLOC();

    CPU_CRITICAL_ENTER();
    p_tcb->TaskState = OS_TASK_STATE_SUSPENDED;
    OS_PrioRemove(p_tcb->Prio);              /* 清位图 → 调度器再也选不到它 */
    CPU_CRITICAL_EXIT();

    if (p_tcb == OSTCBCurPtr) {
        OSSched();                           /* 挂起自己：调度点① */
    }
}

/* 恢复任务：插回就绪表并调度一次（对方更高优先级 → 立即抢占） */
void  OS_TaskResume (OS_TCB *p_tcb)
{
    CPU_SR_ALLOC();

    CPU_CRITICAL_ENTER();
    if (p_tcb->TaskState == OS_TASK_STATE_SUSPENDED) {  /* 已就绪则跳过，防重复置位 */
        p_tcb->TaskState = OS_TASK_STATE_RDY;
        OS_PrioInsert(p_tcb->Prio);
    }
    CPU_CRITICAL_EXIT();

    OSSched();                               /* 调度点② */
}

注意 OS_TaskResume 的幂等处理：恢复一个"本来就就绪"的任务时跳过插入——这个细节直接决定下面 demo 的正确性，也是真实 UCOS 会做的检查。优先级保留规则同 UCOS（PDF p.92）：0、1 保留给内核，31 是空闲任务，应用任务用 2~30。

5. 空闲任务与 OSStart：最后两块拼图

µC/OS-III 在 OSInit 里就悄悄创建了空闲任务（OS_IdleTaskInit，PDF p.116），优先级 OS_CFG_PRIO_MAX-1，常驻就绪表——保证位图永不为空（第 7 课练习 7.2 的思考题在此落地）。MiniOS 同款：

/* ---------- MiniOS/os_core.c：OSInit 补空闲任务 + OSStart（第 9 课交付） ---------- */
static  OS_TCB   IdleTask_TCB;
static  CPU_STK  IdleTaskStk[64];
static  void     OS_IdleTask (void *p_arg)      /* 空闲任务：永远最低优先级的"管家" */
{
    for (;;) {
        OSIdleTaskCtr++;                        /* 闲着没事干就数数（调试用） */
    }
}

void  OSInit (void)
{
    OS_ERR  err;
    CPU_DATA  i;

    OS_PrioInit();                              /* ① 位图清零 */
    for (i = 0u; i < OS_CFG_PRIO_MAX; i++) {    /* ② TCB 池清零 */
        OSTCBTbl[i].StkPtr    = (CPU_STK *)0;
        OSTCBTbl[i].Prio      = (OS_PRIO)i;
        OSTCBTbl[i].TaskState = OS_TASK_STATE_SUSPENDED;
        OSTCBTbl[i].TickRemain = 0u;
    }
    OSTCBCurPtr     = (OS_TCB *)0;
    OSTCBHighRdyPtr = (OS_TCB *)0;
    OSPrioCur       = 0u;
    OSPrioHighRdy   = 0u;
    OSRunning       = OS_STATE_OS_STOPPED;
    OSSchedLockNestingCtr = 0u;                 /* 第 6 课调度锁的计数（os_core.h 补声明） */
    OSIntNestingCtr       = 0u;                 /* 第 6 课中断嵌套计数（同上） */

    OSTaskCreate(&IdleTask_TCB, OS_IdleTask, (void *)0,
                 (OS_CFG_PRIO_MAX - 1u), IdleTaskStk, 64u, &err);  /* ③ 空闲任务常驻就绪表 */
}

void  OSStart (OS_ERR *p_err)
{
    if (OSInitialized != OS_TRUE) {             /* 简化版：OSInit 里置位 */
        *p_err = OS_ERR_OS_NOT_INIT;
        return;
    }
    if (OSRunning == OS_STATE_OS_STOPPED) {
        OSPrioHighRdy   = OS_PrioGetHighest();  /* ① 查位图：谁最高谁先跑 */
        OSTCBHighRdyPtr = &OSTCBTbl[OSPrioHighRdy];
        OSTCBCurPtr     = OSTCBHighRdyPtr;
        OSRunning       = OS_STATE_OS_RUNNING;
        OSStartHighRdy();                       /* ② 汇编启动第一个任务（第 8 课）——不返回 */
        *p_err = OS_ERR_FATAL_RETURN;           /* 到不了这里 */
    } else {
        *p_err = OS_ERR_OS_RUNNING;
    }
}

对照教材 OSStart（PDF p.127~129）：取最高就绪优先级 → 取 TCB → 置 OSRunning → OSStartHighRdy 不归路。唯一简化是我们没做"内核任务数量统计"检查——因为 OSInit 已经创建了空闲任务，位图永不为空。

6. 本课交付：第一个多任务 demo

终于到最后一步。两个任务一高一低，用"恢复对方 + 挂起自己"的手势交替（抢占与让出齐活）：

/* ---------- MiniOS/main.c：第 9 课验收 demo ---------- */
#include "os_core.h"
#include "usart.h"

OS_TCB    Task1_TCB;
CPU_STK   Task1Stk[128];
OS_TCB    Task2_TCB;
CPU_STK   Task2Stk[128];

void  task1 (void *p_arg)          /* 低优先级任务（数值 3） */
{
    for (;;) {
        printf("task1 running\r\n");
        OS_TaskResume(&Task2_TCB);     /* 恢复高优先级 task2 → 立即被抢占切换！
                                        * 注意：这行执行后本任务就被切走了，
                                        * 下面的 OS_TaskSuspend 永远执行不到（思考题！） */
        OS_TaskSuspend(&Task1_TCB);
    }
}

void  task2 (void *p_arg)          /* 高优先级任务（数值 2） */
{
    for (;;) {
        printf("task2 running\r\n");
        OS_TaskResume(&Task1_TCB);     /* 恢复低优先级 task1：不切换（自己仍最高） */
        OS_TaskSuspend(&Task2_TCB);    /* 挂起自己 → 让出 CPU 给 task1 */
    }
}

int main (void)
{
    OS_ERR  err;

    HAL_Init();
    uart_init(115200);
    OSInit();                            /* ① 内核初始化（含空闲任务） */

    OSTaskCreate(&Task1_TCB, task1, (void *)0, 3u,  Task1Stk, 128u, &err);
    OSTaskCreate(&Task2_TCB, task2, (void *)0, 2u,  Task2Stk, 128u, &err);

    OSStart(&err);                       /* ② 调度开始：task2 优先跑（数值 2 < 3） */
    for (;;) { ; }                       /* 永不返回 */
}

运行轨迹（值得对着源码逐行推一遍）：

步骤谁在跑动作结果
1—OSStart 查位图：2、3 就绪最高 = 2 → task2
2task2打印 task2串口输出
3task2OS_TaskResume(task1)：task1 已就绪，跳过不切换
4task2OS_TaskSuspend(task2)：清 bit2最高 = 3 → 切到 task1
5task1打印 task1串口输出
6task1OS_TaskResume(task2)：置 bit2，task2 更高立即抢占 → 切到 task2
7task2回到步骤 2，循环task2/task1 无限交替

串口输出：task2 task1 task2 task1 ...。至此，从第 7 课的位图、第 8 课的切换，到本课的调度器——一个五脏俱全的最小内核诞生了。它和 µC/OS-III 的差距只是"功能数量"，不是"机制完整性"。

⚠️ 理解 demo 里"执行不到的代码"：task1 的 OS_TaskSuspend(&Task1_TCB) 每次都在恢复 task2 时被抢走，永远执行不到——所以 task1 始终处于就绪态。这不是 bug，而是抢占式调度的必然：恢复一个更高优先级任务 = 立即切换。把两处 OS_TaskResume 都注释掉再运行，两个任务会先后挂起，就轮到空闲任务数数了（观察 OSIdleTaskCtr）——这个对照实验能让你彻底分清"让出"与"抢占"。

随堂小测

Q1. OSSched 里哪一道闸门负责拦住"中断里调用调度"？

A. OSRunning 运行标志检查

B. OSIntNestingCtr 中断嵌套检查

C. OSSchedLockNestingCtr 锁检查

D. CPU_CRITICAL_ENTER 临界区

查看答案
B。中断中改变就绪集合由 OSIntExit 在中断退出时统一调度，任务级 OSSched 若被中断调用会与 OSIntExit 冲突，所以直接返回（PDF p.133）。

Q2. OS_TaskResume 恢复了一个更高优先级任务，会发生什么？

A. 目标任务被立即抢占切换执行

B. 目标任务保持挂起等待调度

C. 当前任务继续运行直到延时

D. 系统进入空闲任务运行

查看答案
A。OS_TaskResume 末尾调用 OSSched，查到最高就绪优先级比当前高 → 挂起 PendSV，恢复动作本身变成一次抢占切换（PDF 表 8.2.1 中"任务的挂起状态被终止"）。

Q3. MiniOS 创建空闲任务的根本原因是？

A. 提供系统时基节拍服务

B. 保证就绪位图永不为空，调度恒有解

C. 恢复所有被挂起的任务

D. 统计 CPU 使用率

查看答案
B。空闲任务常驻最低优先级位（bit0），OS_PrioGetHighest 的 while 循环永不越界，系统永远有任务可跑（PDF p.113 的 OS_PrioInit 注释）。

Q4. OSTaskCreate 中需要进临界区保护的操作是？

A. 初始化任务栈帧

B. OS_PrioInsert 置位操作

C. 任务函数参数赋值

D. 空闲任务计数器自增

查看答案
B。栈初始化只碰任务私有数据，无需保护；位图是全局共享结构，置位必须与调度器的读取互斥（PDF p.126 的 CPU_CRITICAL_ENTER）。
