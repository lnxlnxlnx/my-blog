第 5 课：规范总览与排版注释

从"能跑"到"好看"：正点原子《嵌入式单片机 C 代码规范与风格 V1.1》第 1、2 章（PDF p.3~15）

本课目标：你的代码能跑，但别人（包括三个月后的你）读得懂吗？学完你能说出正点原子规范的四大原则、背得出缩进/行宽/括号/空格四条硬规则，并会写标准的文件头注释、函数说明注释和对齐的行内注释。本课约 45~60 分钟，最后两个练习直接拿你工程里的 lvgl_2048.c 开刀。

1. 规范说明与四大原则

正点原子团队写这份规范的动机很朴素：团队壮大了，代码风格五花八门，维护成本爆炸。新代码必须统一风格，老代码逐步重构，最终达到"统一风格、便于阅读、便于使用、便于移植、便于维护"（PDF p.3）。核心就四条原则：

  1. 简单、明了、清晰：代码首先是写给人看的，可读性优先于性能！规范原文的原话是："尤其是当你写的代码交给他人去维护的时候，请不要祸害别人！"
  2. 精简：一个 1000 多行的函数和一个最多 100 行的函数，谁好看？代码越长越容易出错，没用的代码和变量要及时清理，重复代码提炼成函数。
  3. 保持第三方代码风格：HAL 库、FATFS、LVGL、FreeRTOS、lwIP 这些第三方代码一律不改其风格。你的应用代码用自己的规范，与第三方库的接口程序允许两种风格并存。
  4. 减少封装：切记，不要对第三方代码库二次封装！

⚠️ 第 4 条是重点。ST 官方 Cube 库为了"统一风格"，把 FreeRTOS 的 API 包了一层，结果无数客户跑来问：你们教程里的 xTaskCreate 和 ST 的 osThreadNew 有什么区别？——没有任何区别，纯属白包一层，还给学习者带来困惑（PDF p.3）。所以你的 LVGL 代码就直接调 lv_obj_create、FreeRTOS 就直接调 xTaskCreate，别给它们套一层 my_gui_create_button()、my_rtos_create_task()。

💡 记忆锚点："简单、精简、尊重第三方、不加壳"—— 写完代码问自己：这段代码三个月后还能一眼看懂吗？如果答案犹豫了，就按本课往下学。

2. 排版格式：代码缩进

缩进规则只有一条，但有讲究（PDF p.5）：

  • 统一用 TAB 键缩进，且 TAB 设为 4 个字符
  • 但 TAB 必须用空格替代——不同编译器/阅读软件对 TAB 的渲染长度不一样，用 txt 打开 .c 文件就现原形；空格替代后任何软件打开都一样
  • MDK 设置：Configuration → Edit → C/C++ Files 勾选 Insert spaces for tabs；再在 General Edit Settings 勾选 View White Spaces，就能用"点"看到所有缩进是不是空格
  • 注意：注释的缩进对齐也统一用空格填充的 TAB，否则注释会错位
/* 反例：混用 TAB 与空格，换软件打开后注释列全错位 */
void funa(void)
{
	int count = 0;				/* 这里是真 TAB，长度不可控 */
	for (int i = 0; i < 10; i++)
	{
		count += i;				/* 这里 4 空格，和上一行对不齐 */
	}
}

/* 正例：全部用 4 空格填充，任何软件打开都对得齐齐整整 */
void funa(void)
{
    int count = 0;              /* 注释和代码一起对齐 */
    for (int i = 0; i < 10; i++)
    {
        count += i;             /* 多级缩进依然对齐 */
    }
}

3. 代码行规范

几条硬规则，全部在 PDF p.5~7：

  • 每行不超过 80 列。超长时在低优先级操作符处换行，操作符放新行之首，新行适当缩进与上一行对齐
  • 相对独立的程序块之间、变量说明之后、函数之间必须加空行
  • 一行只写一条语句，禁止 a = x+y; b = x-y; 这种挤一行的写法
  • 禁止连续赋值 a = b = 0;，拆成两行
  • if、for、do、while、switch 等语句单独占一行；其执行语句无论多少条都必须加 {} ，唯一例外是 while 后面确实没有代码
/* 反例：一锅端 */
void funa(void)
{
    if (p_gpiox->IDR & pinx) return 1; else return 0;
    a = b = 0;
    while (((RCC->CR & (1 << 17)) == 0) && (retry < 0X7FFF)) { retry++; }
}

/* 正例：逐条拆开，括号齐全 */
void funa(void)
{
    if (p_gpiox->IDR & pinx)
    {
        return 1;               /* pinx 的状态为 1 */
    }
    else
    {
        return 0;               /* pinx 的状态为 0 */
    }

    a = 0;                      /* 连续赋值拆开 */
    b = 0;

    while (((RCC->CR & (1 << 17)) == 0) && (retry < 0X7FFF))
    {
        retry++;                /* while 有语句就必须加 {} */
    }
}

80 列换行示例（PDF p.5）：操作符 + 放新行之首，第二行与上一行对齐：

perm_count_msg.head.len = NO7_TO_STAT_PERM_COUNT_LEN
                         + STAT_SIZE_PER_FRAM * sizeof(uint32_t);

4. 括号与空格

括号规则（PDF p.8）：

  • 单片机开发中，左大括号 { 一律新起一行，且与程序块起始处同一列（教材明确把 for (...) { 这种行尾大括号列为"不规范的写法"）
  • else 独立成行，不跟在大括号后面
  • 例外：while (xxx); 空等待确实没有代码时，可以不加 {}

空格规则八条（PDF p.9），挑最常踩的几条：

  • 关键字 if/switch/case/for/do/while 后面加空格；但 sizeof/typeof/__attribute__ 后面不加（它们像函数调用）
  • 指针的 * 靠变量名：char *ptr; 而不是 char* ptr;
  • 二元/三元运算符两侧各一个空格：= + - < > * / % == != ? :
  • 一元运算符后不加空格：& * + - ~ ! sizeof；++ -- 前后都不加
  • . 和 -> 前后不加空格；逗号、分号只在后面加空格
/* 反例：教科书级丑代码 */
void test_error(datax* p,int num,char baseval)
{
    int x1 ,x2;
    int t=0;
    x1=32;
    x2=23;
    for(t=0;t<=num;t ++ ) /*循环赋值*/
    {
        datax -> buf[ t ]=x1*(x2+t)+baseval;
    }
}

/* 正例：运算符两侧空格、* 靠变量、注释两侧留白 */
void test_error(datax *p, int num, char baseval)
{
    int x1, x2;
    int t = 0;
    x1 = 32;
    x2 = 23;
    for (t = 0; t <= num; t++)     /* 循环赋值 */
    {
        datax->buf[t] = x1 * (x2 + t) + baseval;
    }
}

💡 你现在可以顺手看看 BSP/LVGL_APP/lvgl_2048.c 和 lvgl_snake.c：2048 用的是行尾大括号，snake 用的是新起一行，两个文件风格还不统一。学完这节，你就有依据把它们统一成教材风格了。

5. 注释风格：做什么，而不是怎么做

注释的核心原则（PDF p.10）：告诉别人代码做了什么（结果），而不是怎么做的（过程），并且不过度注释。正点原子统一采用 doxygen 风格：

  • 代码行内注释：/* ... */，/* 和 */ 内侧各留一个空格
  • 文件/函数说明注释：/** ... */ 多行块，每行行首 * 对齐在一列
  • 放弃 // ... 和 /// ... 风格；当且仅当屏蔽部分功能代码（留着以后调试用）时才可以用 //，比如注释掉一行 printf 调试输出
/* 反例：用 // 写正式注释（教材明确放弃这种风格） */
// 检查超时
// 如果超时就清除标记并返回
if (timeout == 0)
{
    //printf("r fifo time out\r\n");
    SDMMC1->ICR = 0X1FE00FFF;
    return SD_DATA_TIMEOUT;
}

/* 正例：正式注释用 /* */，// 只留给被屏蔽的调试代码 */
if (timeout == 0)
{
    //printf("r fifo time out\r\n");
    SDMMC1->ICR = 0X1FE00FFF;                /* 清除所有标记 */
    sys_intx_enable();                       /* 开启总中断 */
    return SD_DATA_TIMEOUT;
}

⚠️ 注释会"撒谎"：代码改了，注释忘了改，比没有注释更坑人。看看你自己的 lvgl_snake.c 第 28 行——"游戏状态变量c"，结尾多了个字母 c 的小笔误；第 29 行的注释又长又绕。写注释要像写代码一样校对。

6. 三类注释模板

6.1 文件信息注释（PDF p.11）

文件开头放整体说明：文件名、作者、版本、日期、简要说明、版权、注意事项。分隔线规定为 100 个 *，注释块和第一行代码之间必须空一行：

/**
******************************************************************************
 * @file        lvgl_2048.c
 * @author      你的名字
 * @version     V1.0
 * @date        2026-08-27
 * @brief       2048 游戏：核心逻辑与 LVGL 界面
 * @copyright   Copyright (c) 2026, 个人学习工程
******************************************************************************
 * @attention
 *
 * 平台: STM32F407 探索者 + 正点原子 4.3 寸屏
 * 依赖: LVGL v8, AT24C02 驱动 (BSP/24CXX)
 *
 * 修改说明
 * V1.0 20260827
 * 第一次发布
 *
******************************************************************************
 */

#include "lvgl_2048.h"

6.2 函数注释（PDF p.12）

放在函数实体前、紧挨函数：@brief 概要、@param 参数、@arg 参量列表、@note 注意事项、@retval 返回值：

/**
 * @brief 将一个方向上的 16 位行数据进行滑动与合并
 * @param line: 指向 4 元素数组, 原地修改为合并后的行
 * @param score_acc: 指向累加分数, 合并时累加
 * @retval true: 该行有移动, false: 该行无变化
 * @note  合并只进行一次, 2048 规则: 4 4 4 4 -> 8 8
 */
static bool slide_and_merge_line(uint16_t *line, uint32_t *score_acc)
{
    ...
}

6.3 行内代码注释（PDF p.14）

短注释放代码后面，多行注释尽可能对齐；长注释放到被注释代码的前面：

/* 反例：注释乱飞，比代码本身还难看 */
RCC->CR = 0x00000001; /* 设置 HSI 开启 */
RCC->CFGR = 0x00000000;/* CFGR 清零 */
RCC->PLLCFGR = 0x00000000;             /* PLLCFGR 清零 */

/* 正例：注释对齐，一眼扫过 */
RCC->CR = 0x00000001;                  /* 设置 HSI 开启 */
RCC->CFGR = 0x00000000;                /* CFGR 清零 */
RCC->PLLCFGR = 0x00000000;             /* PLLCFGR 清零 */

sys_clock_set(plln, pllm, pllp, pllq); /* 设置时钟 */

1️⃣ 用编辑器打开 BSP/LVGL_APP/lvgl_2048.c，你会发现它没有文件头注释（@file 块缺失），而且顶部全是 // 风格注释。

2️⃣ 按 6.1 模板补一个完整的文件头：@file / @author / @version / @date / @brief / @attention（写上"依赖 LVGL v8 与 BSP/24CXX"），分隔线按规范用 100 个 *，并和 #include 之间空一行。

3️⃣ 顺手把第 8 行起几处 // 正式注释改成 /* */ 风格（仅保留真正"屏蔽调试代码"的 //）。

验收标准：文件头字段齐全、分隔线 100 个 *、#include 前空一行、编译零警告。

练习 5.2（重构练习）：给"坨代码"格式化

1️⃣ 下面的代码违反了一大堆本课规则，先自己找出全部问题：

void funa(void)
{
     if(!valid_ni(ni)) return 1;
     else return 0;
     while(x==0){ retry++; }
     a = x+y; b = x-y;
     a = b = 0;
}

2️⃣ 按教材规则重写：大括号新起一行且与块同列、if/else 分块、while 非空必须加 {}、一行一语句、连续赋值拆开、运算符两侧加空格。

3️⃣ 写完后逐条对照本课 2、3、4 节的检查清单自查一遍。

验收标准：对照清单逐条勾选全部通过；代码在你脑子里的"第一印象"从烦躁变清爽。

随堂小测

Q1. 正点原子规范对代码缩进的要求是？

A. 直接用 TAB 字符缩进

B. TAB 缩进，但用 4 个空格替代

C. 一律使用 2 个空格

查看答案
B。统一 TAB=4 字符，且用空格填充替代，避免不同软件打开时缩进错位（PDF p.5）。

Q2. 一行代码的长度限制是？

A. 60 列

B. 80 列

C. 120 列

查看答案
B。超过 80 列在低优先级操作符处换行，操作符放新行之首（PDF p.5）。

Q3. 单片机开发中，左大括号 { 应该放在哪里？

A. 代码行尾（K&R 风格）

B. 新起一行，与块起始同列

C. 与 if 语句缩进一级

查看答案
B。教材明确把行尾大括号列为不规范写法，{ 一律新起一行且同列（PDF p.8）。

Q4. 什么时候才允许使用 // 注释？

A. 屏蔽调试代码时

B. 行内短注释都可以

C. 任何地方都不允许

查看答案
A。正式注释统一 /* */，仅屏蔽功能代码（如注释掉的 printf）时可用 //（PDF p.10）。
