模板方法与装饰器

架构与设计模式 · 课程 0007 · 预计 20 分钟

这课两个都叫「方法/装饰」的模式:一个你可能早就见过——第一课的 BaseTrainer.run;一个是 Python 最标志性的语法糖装饰器。两个都是 AI 代码里的高频面孔。

知识点 1:模板方法——骨架定在基类,钩子留给子类

模板方法(Template Method):基类把「流程」写死,把流程中「会变的步骤」留成钩子,子类只填钩子(官方讲解)。你第一课就见过:

from abc import ABC, abstractmethod


class BaseTrainer(ABC):
    def run(self, data):                     # ← 这就是「模板方法」:骨架
        x, y = self.preprocess(data)         #   流程定死,顺序不许改
        model = self.build()
        self.fit(model, x, y)
        return self.evaluate(model, x, y)

    @abstractmethod
    def preprocess(self, data): ...          # 钩子 1:子类填
    @abstractmethod
    def build(self): ...                     # 钩子 2
    @abstractmethod
    def fit(self, model, x, y): ...          # 钩子 3
    @abstractmethod
    def evaluate(self, model, x, y): ...     # 钩子 4


class SVMTrainer(BaseTrainer):               # 只填空,不碰骨架
    def preprocess(self, data): return scale(data)
    def build(self):       return SVC()
    def fit(self, model, x, y): model.fit(x, y)
    def evaluate(self, model, x, y): return model.score(x, y)

好处:所有子类共享同一套流程(保证「先清洗、再建模、再评估」的顺序不出错),又各自定制每一步。加一个新模型 = 新类填空,骨架零改动。

知识点 2:钩子还可以给默认实现

钩子不一定要抽象——给个默认实现,子类想改才覆盖:

class BaseTrainer(ABC):
    def after_each_epoch(self, epoch, loss):   # 默认钩子:什么都不做
        pass

    def run(self, data):
        for epoch in range(10):
            loss = self.fit(data)
            self.after_each_epoch(epoch, loss)   # 子类可决定要不要覆盖


class LoggingTrainer(BaseTrainer):
    def after_each_epoch(self, epoch, loss):     # 只覆盖想改的那个钩子
        print(epoch, loss)

这也呼应了上一课的观察者——钩子是一种「写死的观察点」。区别:模板方法的钩子由子类实现;观察者的回调由外部对象注入。

知识点 3:装饰器——不改原函数,再包一层能力

装饰器(Decorator)是结构型模式在 Python 里的天生形态:在不改原函数代码的前提下,给它动态加上行为(计时、日志、缓存、权限……)(官方讲解)。

import functools
import time


def timed(func):
    """装饰器:给函数加上『打印耗时』的能力。"""
    @functools.wraps(func)                  # 保真:保留原函数的名字/文档
    def wrapper(*args, **kwargs):
        t0 = time.perf_counter()
        result = func(*args, **kwargs)
        dt = time.perf_counter() - t0
        print(f"{func.__name__} 耗时 {dt*1000:.1f} ms")
        return result
    return wrapper


@timed                                   # 等价于 train_score = timed(train_score)
def train_score(model, X, y):
    model.fit(X, y)
    return model.score(X, y)


train_score(model, X, y)     # 原函数一行没变,就多了计时能力

关键点:@timed 只是把一个函数替换成包了一层的新函数。因为有了 functools.wraps,外面看起来还是原来的 train_score。

知识点 4:装饰器可以叠加,还能带参数

@timed
@logged          # 多个装饰器 = 从下往上逐层包装
def load(path): ...


def retry(times=3):                      # 带参数的装饰器:多包一层工厂
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for i in range(times):
                try:
                    return func(*args, **kwargs)
                except Exception:
                    if i == times - 1:
                        raise
            return None
        return wrapper
    return decorator


@retry(times=5)                          # 用法:给网络请求加自动重试
def fetch(url): ...

AI 代码和很多框架(Flask 路由、FastAPI、pytest.fixture、click 命令)都在大量用装饰器——认得出 @wraps 和「逐层包装」这个动作,你就能读懂它们了。

知识点 5:什么时候别用

  • 模板方法:子类只有一两个、流程万年不变 → 直接一个函数写完更简单
  • 装饰器:包装一层超过两三层 → 调试时你会疯(看不到原函数了)
  • 装饰器副作用:做了「悄悄的事」(重试、缓存)吗 → 记得文档里写清楚,否则同事会懵

测验 1

模板方法的核心是?

骨架(流程)定在基类,会变的步骤留成钩子,子类只填空——所有子类共享同一套流程。

测验 2

装饰器函数的能力?

装饰器把函数「替换」成包了一层的新函数,原函数本体一行没改,还能多层叠加。

测验 3

写装饰器最好保留?

用 @functools.wraps 保留原名和文档字符串,否则调试和自动文档都会认不出原函数。
