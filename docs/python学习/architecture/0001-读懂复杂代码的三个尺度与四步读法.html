读懂复杂代码:三个尺度与四步读法

架构与设计模式 · 课程 0001 · 预计 15 分钟

你说「很多 AI 写的代码我都不是很懂」。这很正常——AI 生成的代码是为扩展写的,不是为一口气读完写的:它有抽象基类、有注册表、有工厂函数,把逻辑拆得到处都是。这节课给你一张地图和一套方法,让你以后拿到任何代码都能说出它的形状。

为什么复杂代码难读

复杂代码难读,通常因为三个原因叠加:

  • 间接层多:调用链弯弯绕绕(接口 → 抽象类 → 实现),你顺着调用链找,很容易迷路
  • 命名抽象:类名叫 BaseTrainer、Handler、Registry,不跑一遍不知道干嘛
  • 模式不熟:代码的「套路」你没见过,就不知道哪部分是骨架、哪部分是血肉

好消息:这三种难读,都有对应的解药。本节课解决「模式不熟」和「间接层多」。

第一个认知:代码有三个尺度

函数

一个行为,几十行内。读它只看:输入、输出、副作用。

类

一组状态 + 行为,几百行内。读它只看:有哪些字段、公开哪些方法。

模块/包

一组类的协作,几千行以上。读它只看:入口在哪、谁依赖谁。

看不懂,往往是因为你在一层想搞懂另一层的事。比如:你非要读完每个函数才敢说「我懂这个模块」——其实你只需要模块层的答案(入口、依赖)。反过来,想改一个函数,却先去读整个包的依赖图——那也是浪费。先问自己:我现在在哪个尺度?

第二个认知:架构 vs 设计模式

  • 架构(Architecture):模块之间怎么组织——谁在上层、谁在下层、依赖朝哪个方向。是代码库的「宏观形状」。
  • 设计模式(Design Pattern):类与类之间协作的经典套路,有名字。是「微观套路」。

一句话记忆:架构是地图,模式是招式。地图决定你去哪,招式决定单挑时怎么出拳。本系列课程先练招式(设计模式),再学地图(架构),最后用两者去读真实项目。

设计模式地图:三大类 22 式

「设计模式」出自 GoF 四人的书,一共 22 个常用模式,按用途分三类(Refactoring Guru 目录,每个模式都有 Python 示例):

创建型 (Creational)

怎么造对象:工厂方法、抽象工厂、建造者、原型、单例。

结构型 (Structural)

类和对象怎么组合:适配器、桥接、组合、装饰器、门面、享元、代理。

行为型 (Behavioral)

对象之间怎么分工协作:策略、观察者、模板方法、命令、状态、迭代器……

不用背,先混个脸熟。本课程只深入学最高频的七八个,其余的认得出、查得到就行。

技能:读代码四步法

面对陌生代码(尤其是 AI 生成的),按这四步走,顺序不能乱:

  1. 找入口:main()、脚本末尾、CLI 定义、测试里的调用处。入口是阅读的起点。
  2. 画依赖:顺着 import 和构造函数的参数,画出「谁依赖谁」。箭头方向就是信息流方向。
  3. 找抽象:标出接口/抽象基类(约定),和具体实现(兑现约定的地方)。骨架在这一步就清楚了。
  4. 看实现:只在你要改、要修的地方,才深入读具体类。

这四步的核心理念:先看形状,再看血肉。90% 的代码,你只需要前两步的答案。

实战:一段 AI 风格的代码

下面是一段典型的 AI 生成训练代码(和你的 ML 知识同一个领域,读起来最容易)。先用四步法拆,再看我的拆法:

class BaseTrainer(ABC):
    """所有训练器的公共骨架。"""
    def run(self, data):            # 流程定死在抽象层
        x, y = self.preprocess(data)
        model = self.build()
        self.fit(model, x, y)
        return self.evaluate(model, x, y)

    @abstractmethod
    def preprocess(self, data): ...  # 四个钩子,子类填空
    @abstractmethod
    def build(self): ...
    @abstractmethod
    def fit(self, model, x, y): ...
    @abstractmethod
    def evaluate(self, model, x, y): ...

class TrainerRegistry:
    """把『名字 → 训练器类』登记起来。"""
    _registry = {}

    @classmethod
    def register(cls, name):
        def wrap(trainer_cls):
            cls._registry[name] = trainer_cls
            return trainer_cls
        return wrap

@TrainerRegistry.register("svm")
class SVMTrainer(BaseTrainer):
    def preprocess(self, data):
        return StandardScaler().fit_transform(data), ...
    def build(self):
        return SVC()
    def fit(self, model, x, y):
        model.fit(x, y)
    def evaluate(self, model, x, y):
        return model.score(x, y)

def make_trainer(name):              # 按名字造对象
    return TrainerRegistry._registry[name]()

四步拆法:

  1. 入口:make_trainer("svm") 造对象,trainer.run(data) 执行。
  2. 依赖:调用方只依赖 BaseTrainer 和 TrainerRegistry,不依赖 SVMTrainer。箭头指向抽象。
  3. 抽象:BaseTrainer.run 是骨架,4 个 @abstractmethod 是契约。
  4. 实现:SVMTrainer 只负责填空,registry 负责登记。

它用到的模式(先记住名字,细节后面逐课学):模板方法(Template Method,流程定在抽象类)、工厂方法(Factory Method,按名字造对象)、注册表(Registry,名字→类映射)。

关键洞见:读懂这段代码,你不需要读 SVMTrainer 的任何一个方法。抽象的功劳——这就是 AI 代码「绕」的原因,也是它值得学的原因。
