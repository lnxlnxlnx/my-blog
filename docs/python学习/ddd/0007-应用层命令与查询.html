应用层:应用服务 / 命令 / 查询(CQS)

DDD 与六边形架构 · 课程 0007 · 预计 25 分钟

领域层讲完了,向外一层是应用层。它有两个核心:应用服务(编排一个用例)和命令-查询分离 CQS(改数据走命令 Command,读数据走查询 Query)。本课讲清「一个外部请求 → 命令/查询 → 应用服务 → 领域」这条线,以及那个 bus 是什么。

知识点 1:命令 Command——表达"用户想做什么"

命令是个数据对象,描述一次"改变状态的意图"(CreateUserCommand),它不执行业务,只是"信号的载体"。改数据(增删改)归命令:

from dataclasses import dataclass

@dataclass
class CreateUserCommand:          # 命令:意图的数据,不含逻辑
    email: str
    name: str

命令是"需求说明书":把一个参数传进去,交给处理器去执行。它和架构课学的 Command Pattern 类似但更轻——这里它主要是数据结构(CQS)。

知识点 2:查询 Query——表达"想读什么"

查询表示"找东西"的意图,只读不改。按 CQS,读和写在命令/查询上分开:

@dataclass
class FindUsersQuery:
    page: int = 1
    limit: int = 20

重要:查询不产生副作用(不写库、不发文件)。项目里查询可以直接绕过领域层和仓储,直接查数据库——因为只是读(读模型可直查)。写走命令、读走查询,代码意图更清楚。

知识点 3:应用服务 = 命令/查询的处理器

应用服务把命令变成领域动作:拿命令 → 造/取领域对象 → 执行领域方法 → 存库 → 返回。它是"一个用例一个服务":

class CreateUserService:                       # 应用服务(命令处理器)
    def __init__(self, repo):                  # 依赖注入端口(0008 讲)
        self.repo = repo
    def handle(self, cmd: CreateUserCommand):
        user = User(uuid(), Email(cmd.email))  # 命令→领域对象
        self.repo.save(user)                   # 经端口存库
        return user.id

注意:应用服务自己不含业务规则(那在领域层);它只编排——把外面装成领域类型、叫领域方法、存取数据。业务判断都往下推给实体/值对象/领域服务。

知识点 4:Command Bus / Query Bus——解耦"谁发谁处理"

不直接 import 服务,而是发到一个 bus,由 bus 路由到对应处理器。这样调用方(repository)不知道也不关心"谁来做",避免耦合(想想 0006 的事件 bus 是一个思路):

class CommandBus:
    def __init__(self):
        self._handlers = {}
    def register(self, command_type, handler):
        self._handlers[command_type] = handler
    def execute(self, command):
        return self._handlers[type(command)].handle(command)

bus = CommandBus()
bus.register(CreateUserCommand, CreateUserService(repo))
user_id = bus.execute(CreateUserCommand(email="a@x.com", name="Ann"))

这就是 NestJS CQRS 的 command bus。好处:从任何地方发命令都不 import 具体服务;改实现不碰调用方。

知识点 5:命令别调命令——用事件衔接

项目强烈建议别让一个命令处理器去执行另一个命令(Command→Command 变耦合成链)。要用事件:Command → Event → Command。命令 A 完成就发布事件,事件的处理器再去发命令 B。这样链条是松耦合的,可扩展。

测一测(先自己答,再点答案)

测验 1

"创建用户"这个意图用什么表达?

改状态的操作(Create/Update/Delete)用 Command;读数据用 Query。

测验 2

查询 Query 应当?

Query 无副作用,只读取;写归 Command。读模型可绕过仓储直查库。

测验 3

应用服务是否该含业务规则?

应用服务只编排(转换类型、调领域方法、存库),业务规则在领域层。

测验 4

想让命令处理器别直接调另一个命令,用?

Command→Event→Command,用事件而不是命令直接调命令,保持松耦合。
