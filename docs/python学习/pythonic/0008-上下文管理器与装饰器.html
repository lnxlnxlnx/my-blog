上下文管理器(with)与装饰器

Pythonic 代码 · 课程 0008 · 预计 25 分钟

这是收尾课,讲两个「C 里完全没有、Python 特有」的语法糖。with 替你管「用完要收拾」的资源(文件、连接、锁);装饰器让你不改函数本体给它加能力(计时、重试、日志)。两个都是 Python 生态里无处不在的关键词。

知识点 1:with——「用完自动关」,不用手动 close

C 思维(手动 open / 用完 close,还容易漏):

f = open("data.txt")     # C:open-用-close
data = f.read()
f.close()                # 忘了怎么办?异常时更麻烦

Pythonic——with 进入时打开,离开时自动调用 close(即使中间报错也保证关闭):

with open("data.txt") as f:
    data = f.read()      # 只要缩进块内,用完自动关

要点:凡是「有资源要释放」的对象(文件、锁、数据库连接、重定向),都用 with ... as x:。文件读写经常配合上一课的 pathlib:Path.read_text() 内部其实也是 with。

知识点 2:with 也能同时管多个 / 配合 generators

要同时读写两个文件、或开多个资源,with A() as a, B() as b: 一行搞定。

with open("in.txt") as fin, open("out.txt", "w") as fout:
    fout.write(fin.read())

还有用 @contextmanager 把「先做A、finally做B」的逻辑变成 with 块——后面装饰器一同学到。

知识点 3:装饰器——不改原函数,给它包一层能力

C 程序员想给函数加计时,常改函数内部或复制代码。装饰器让你外挂一个「包装层」:@timed 只是把函数替换成包了一层的版本。

import functools, time

def timed(func):
    @functools.wraps(func)   # 保留原名/文档,别让调试认不出原函数
    def wrapper(*args, **kwargs):
        t0 = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"{func.__name__}: {time.perf_counter()-t0:.4f}s")
        return result
    return wrapper

@timed
def slow(x):
    return x * x

slow(5)      # 原函数一行没改,就多了计时

关键:@timed 等价于 slow = timed(slow)。装饰器就是一个「接收函数、返回新函数」的函数。

知识点 4:装饰器的常见用法

除了计时,AI/框架代码里到处都是:

# 缓存(自动 memoize,免写手写缓存字典)
from functools import lru_cache
@lru_cache(maxsize=None)
def fib(n):
    return n if n < 2 else fib(n-1) + fib(n-2)

# 官方自带:注册去重 / 折叠
from functools import reduce, wraps
# 常用模式:日志、权限校验、重试、记时

@lru_cache 给纯函数加记忆化,是「免手写缓存」的头号例子;框架里 Flask 路由 @app.route、pytest 的 @fixture 也都是装饰器——现在你读 AI 代码能认出「这是在包一层」了。

知识点 5:什么时候别用

  • with:对象不需要释放资源 → 别硬套;别用它把两件无关的事塞一块
  • 装饰器:包装超过两三层 → 调试会过不了原函数;装饰器做了「悄悄的事」(缓存/重试)→ 记得写文档说明,否则同事懵

测验 1

读文件,最省心写法?

with ... as f: 自动在离开块时关闭文件,异常也安全。

测验 2

@timed 实际等价于?

@timed 是把 foo 替换成 timed 返回的包装函数,即 foo = timed(foo)。

测验 3

写装饰器最好保留原函数的?

用 @functools.wraps 保留原名和文档字符串,否则调试/文档认不出。

测验 4

免手写缓存/记忆化的现成装饰器?

functools.lru_cache 给纯函数加记忆化,自动缓存计算结果。
