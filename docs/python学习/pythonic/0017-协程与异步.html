协程与异步 asyncio

Pythonic 代码 · 课程 0017 · 预计 25 分钟

你学过多线程(0014)知道「IO 等待能并发」。但线程有开销、有锁。异步(asyncio) 用协程(coroutine)在单线程内实现并发:一个任务在「等 IO」时把控制权让出去,另一个任务接着跑,像一张很多人的合作表。本课讲清 asyncio 的思维与基本用法。

先校正一个常见误解

异步不是多线程,它是单线程事件循环。好处:没有锁、没有线程切换开销、能开海量「连接」。代价:你的 IO 必须用「异步版本」的函数(不能直接套同步的 time.sleep / requests.get)。这也是「yield/生成器」在上一课打的基础——协程就是这个思想的正式化。

知识点 1:async / await——协程函数

async def 定义协程函数;调用它不执行函数体,而是返回一个协程对象;真正跑要靠事件循环。await 等一个异步操作完成,同时把控制权让回事件循环:

import asyncio

async def hello():
    print("开始")
    await asyncio.sleep(1)     # 等 1 秒(异步版 sleep,期间让出控制权)
    print("结束")

# 要真正运行,用 asyncio.run
asyncio.run(hello())           # 开始 ... (1秒) ... 结束

要点:await 只能在 async def 里用;asyncio.sleep 是异步版 sleep。想跑一个协程用 asyncio.run(...)。

知识点 2:并发跑一堆任务——asyncio.gather

像线程池 Executor.map 一样,asyncio.gather 并发地跑多个协程并收集结果:gather 时间 ≈ 最慢的一个,而不是相加。

import asyncio

async def fetch(i):
    await asyncio.sleep(1)     # 假装网络请求
    return i * 10

async def main():
    results = await asyncio.gather(fetch(1), fetch(2), fetch(3))
    print(results)             # [10, 20, 30] —— 3 个各等 1 秒,1 秒完成

asyncio.run(main())

gather(*coros) 并发等全部完成、按顺序返回结果。三个 sleep 1 秒的并发 ≈ 1 秒,不是 3 秒。

知识点 3:更 Pythonic 的并发——asyncio 版 HttpClient

真实网络请求要「异步版」的 HTTP 库。标准库 urllib 是同步的;第三方 aiohttp 才是异步版本(已经帮你装了)。并发抓多个 URL:

import asyncio
import aiohttp

async def get(url):
    async with aiohttp.ClientSession() as s:
        async with s.get(url) as r:
            return r.status

async def main():
    urls = ["https://httpbin.org/get" for _ in range(5)]
    statuses = await asyncio.gather(*(get(u) for u in urls))
    print(statuses)            # [200, 200, 200, 200, 200]

asyncio.run(main())

注意 async with 是「异步上下文管理器」,对应同步的 with。一句话区分:requests=同步、aiohttp=异步,想并发抓取用 aiohttp + asyncio。

知识点 4:超时与并行数量控制(基础用法)

异步记得设超时免得挂死;并发太多也用 asyncio.Semaphore 限制同时数量:

import asyncio

async def slow(x):
    await asyncio.sleep(1)
    return x

async def main():
    # 超时:超过 0.5 秒就抛 TimeoutError
    try:
        await asyncio.wait_for(slow(1), timeout=0.5)
    except asyncio.TimeoutError:
        print("超时了")

    # 同时最多 2 个
    sem = asyncio.Semaphore(2)
    async def limited(x):
        async with sem:
            return await slow(x)
    rs = await asyncio.gather(*(limited(i) for i in range(4)))

asyncio.run(main())

wait_for(coro, timeout) 限时;Semaphore(n) 限并发数。这两招加上 gather 就能处理绝大多数基础异步 IO 需求。

知识点 5:何时用异步、何时别用

  • 适合:大量网络/数据库/IO 等待、长连接、Web 服务(能扛海量并发连接)
  • 不适合:纯计算(和 GIL 一样不会并行)、代码到处都是同步阻塞调用(混着会很别扭)
  • 从「同步 repo 改造」第一步:把 time.sleep、requests.get 换成 asyncio.sleep、aiohttp

asyncio 并发靠什么实现?

测验 2

定义协程函数用哪个关键字?

测验 3

并发跑一堆协程并收集结果,用?

gather(*coros) 并发等全部完成并按序收集结果,像 Executor.map。

异步版本 HTTP 库是?

requests/urllib 同步;aiohttp 异步,配合 asyncio 并发抓取。
