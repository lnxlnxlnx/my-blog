Lesson 0010 · Svelte 组件

Svelte 是博客的交互组件框架：负责按钮、下拉菜单、搜索框这类"有状态、会响应"的 UI。它的核心卖点是响应式——变量一变，页面自动更新，你不用手动去改 DOM。

今天这节课的收获：读懂 LightDarkSwitch.svelte（右上角的主题切换按钮）。

1. .svelte 文件的组织

<script lang="ts">
// 1. 脚本区：状态变量 + 逻辑
let count = 0;
function increment() { count++; }
</script>

<!-- 2. 模板：HTML + {变量} + 事件 -->
<button onclick={increment}>
    点我（当前 {count}）
</button>

<style> 按钮样式 </style>  // 3. 组件私有样式

和 .astro 很像，但有一个巨大区别：Svelte 变量是响应式的——count 一加，按钮文本自动变 "当前 1"。在 Astro 的 script 里你不会想要这样，但在组件里这是常态。

2. $state：Svelte 5 的响应式声明

博客用的是 Svelte 5。LightDarkSwitch.svelte 第一行真实代码：

let mode: LIGHT_DARK_MODE = $state(LIGHT_MODE);
let displayedMode: LIGHT_DARK_MODE = $state(LIGHT_MODE);

function switchScheme(newMode: LIGHT_DARK_MODE) {
    mode = newMode;              // 一赋值，用到 mode 的地方全自动更新
    setTheme(newMode);           // 同时把选择存起来
}

$state(初始值) 把变量变成"响应式状态"。之后你正常赋值就行，Svelte 负责刷新 UI。这就是"框架帮你管理 DOM"。

3. onMount：组件挂载后执行一次

LightDarkSwitch.svelte 里的 onMount 做初始化：

import { onMount } from "svelte";

onMount(() => {
    // 组件出现在页面后：读取存的主题并应用
    const storedTheme = getStoredTheme();
    mode = storedTheme;
    updateDisplayedMode();

    // 监听系统主题变化
    const mediaQuery = window.matchMedia("(prefers-color-scheme: dark)");
    mediaQuery.addEventListener("change", updateDisplayedMode);

    // 返回清理函数：组件销毁时移除监听（避免内存泄漏）
    return () => mediaQuery.removeEventListener("change", updateDisplayedMode);
});

你全认识：onMount(() => {...}) 是回调；window.matchMedia、addEventListener 是第八课的 DOM/事件；return () => ... 是"清理钩子"——组件没了，监听也拆掉。没有新概念，只是新框架把它们拼起来。

4. 模板里的条件类和属性

LightDarkSwitch.svelte 模板的真实片段：

<div class="absolute" class:opacity-0={displayedMode !== LIGHT_MODE}>
    <Icon icon="material-symbols:wb-sunny-outline-rounded"></Icon>
</div>

<DropdownItem
    isActive={mode === LIGHT_MODE}
    onclick={() => switchScheme(LIGHT_MODE)}
>
    {i18n(I18nKey.lightMode)}
</DropdownItem>
  • class:opacity-0={条件}：条件为真就加这个类（Svelte 的"条件类"语法）
  • isActive={mode === LIGHT_MODE}：把值传进子组件（props，属性）
  • onclick={() => switchScheme(LIGHT_MODE)}：点击回调——第二课学过的箭头函数
  • {i18n(...)}：模板里插入 JS 表达式结果

5. 更多例子：在项目里找

打开 src/components/ 下的几个 .svelte 文件（比如 interactive/Search.svelte），找一找：

  1. 有没有 $state？
  2. 有没有 onMount？
  3. 模板里有没有 {表达式} 和 onclick={...}？

你很快会发现，所有组件的骨架都一样——框架虽多，JS 底子不变。
