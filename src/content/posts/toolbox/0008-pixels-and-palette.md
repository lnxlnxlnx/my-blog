# 像素与调色板

屏幕上的每个点是怎么来的（《BMP 图片文件详解》第 1 部分：位图与调色板概念）

**本课目标：**搞懂"位图"到底是个什么东西——屏幕是像素矩阵，颜色是 RGB 三个分量按 0~255 量化出来的。然后掌握调色板这个经典省内存技巧：为什么 16 色图只要 20KB 而真彩色要 120KB。最后落到你的板子上：为什么 LVGL 用 16 位 RGB565 而不是 24 位。这是后面读懂 BMP 文件格式的地基。

## 1. 位映象设备：屏幕就是像素矩阵

普通显示器由密密麻麻的点构成，每个点叫**像素（Pixel）**。显示时电子枪从左到右扫一行，给每个像素上色，再从上到下扫完一屏（《BMP 图片文件详解》第 1 节 (章节 1)）。防止闪烁要每秒重复几十次，比如分辨率 640×480、刷新率 70Hz，就是每行扫 640 个像素、共 480 行、每秒重复 70 遍。

这种显示器叫**位映象设备**——"位映象"指一个二维像素矩阵。而**位图（Bitmap）**，就是采用位映象方法显示和存储的图像：用数字记录每个像素的颜色，屏幕上就能复现出来。你的 320×240 LCD 本质就是一块 320×240 的像素矩阵，每个像素一个 16 位 RGB565 值。

```text
+------------------ 一行 320 个像素 ------------------+
| (0,0) (1,0) (2,0)  ...  (319,0)   ← 扫描线，从左到右
| (0,1) (1,1) (2,1)  ...  (319,1)   ← 第二行
|   .      .     .        .
|   .      .     .        .
| (0,239)(1,239) ... (319,239)     ← 共 240 行，从上到下
+--------------------------------------- 位映象设备 = 二维像素矩阵
```

把"每个像素存什么"想清楚，后面所有图像格式（BMP、WAV 其实同理）都只是"怎么把这堆数字装进文件"的问题。

## 2. RGB 三原色与量化：0~255 分级

自然界所有颜色都可由红、绿、蓝（R、G、B）组合而成。每种成分按含量分 0~255 共 256 个等级：0 级 = 不含该成分，255 级 = 100% 该成分（(章节 1)）。这种分级就叫**量化**。三通道一组合：256×256×256 ≈ 1600 万种颜色，人眼已经够用了。

教材给出的常见颜色 RGB 值（(章节 1)）：

| 颜色 | R | G | B | 一句话记忆 |
|------|---|---|---|------------|
| **红** | 255 | 0 | 0 | 只有红色成分 |
| **蓝** | 0 | 0 | 255 | 只有蓝色成分 |
| **绿** | 0 | 255 | 0 | 只有绿色成分 |
| **黄** | 255 | 255 | 0 | 红+绿 |
| **紫** | 255 | 0 | 255 | 红+蓝 |
| **青** | 0 | 255 | 255 | 绿+蓝 |
| **白** | 255 | 255 | 255 | 三色拉满 |
| **黑** | 0 | 0 | 0 | 全为零 |
| **灰** | 128 | 128 | 128 | 三等分 |

> 💡 记忆锚点：**黄色 = 红+绿**，想想黑板上的黄色粉笔——光的三原色和颜料三原色（青、品红、黄）是反着来的，别混。屏幕是发光的，所以是加色法。

## 3. 调色板：用索引省内存

一幅长宽各 200 像素、只有 16 种颜色的图，如果每个像素都用 R、G、B 三个字节存：200×200×3 ≈ **120KB**（(章节 1)）。可这图总共只有 16 种颜色，绝大多数字节都在重复！

聪明的做法：先建一张表，每行记录一种颜色的 R、G、B 值；像素里只存"颜色在表的第几行"——即**索引值**。这张表就是**调色板（Palette）**，也叫**颜色查找表 LUT（LookUpTable）**（(章节 1)）。

```text
# 调色板（颜色查找表）：16 行 × 3 字节 = 48 字节
索引  R    G    B
  0  255    0    0      → 红
  1    0  255    0      → 绿
  ...
 15  ...  ...  ...

# 像素数据：每个像素只存 4 位索引（0~15）
像素(0,0) = 0   // 查表得 红
像素(0,1) = 3   // 查表得 第 3 行的颜色
```

算笔账（(章节 1)）：16 种状态只需 4 位，一个像素半个字节。200×200×0.5 ≈ **20KB**，加上调色板表 3×16 = 48 字节。总共约 20KB，是原来的 **1/6**——省多了。

反过来想：**真彩色（TrueColor）**图（256³ 种颜色）就不用调色板——索引也要 24 位才能区分 1600 万行，和直接存 RGB 一样大，还白搭一个 256×256×256×3 字节的巨型调色板，毫无便宜可占（(章节 1)）。所以真彩色直接每像素 3 字节存 RGB，又叫 **24 位色图**。

## 4. 你的屏幕：RGB565 与调色板的关系

你板子上的 LCD 是 320×240，每像素 16 位（`LV_COLOR_DEPTH 16`，RGB565：R 占 5 位、G 占 6 位、B 占 5 位）。用"每像素位数 × 像素数"算一屏显存：

| 色深 | 每像素位数 | 320×240 一屏 | 说明 |
|------|-----------|-------------|------|
| 1 位（黑白） | 1 bit | 320×240÷8 = **9.6KB** | 1 字节存 8 像素 |
| 4 位（16 色） | 4 bit | 320×240÷2 = **37.5KB** | 1 字节存 2 像素（索引） |
| 8 位（256 色） | 8 bit | 320×240 = **75KB** | 1 字节 1 像素（索引） |
| **16 位 RGB565** | 16 bit | 320×240×2 = **150KB** | LVGL 当前配置 |
| 24 位真彩 | 24 bit | 320×240×3 = **225KB** | 每像素 3 字节 |

两个关键结论：

- **为什么 565 省内存**：人眼对绿色最敏感，565 给绿色多留 1 位，视觉损失极小，但比 24 位省 1/3 内存（每像素 2 字节 vs 3 字节）。嵌入式内存金贵，这是行业标准选择。
- **565 和调色板不是一回事**：16 色调色板图每像素存的是"表索引"（4 位）；RGB565 每像素存的是**直接的颜色值**（无表）。前者叫索引色，后者叫直接色。真彩色图（含 24 位）不需要调色板，因为每个像素颜色都不同、查表没意义。

> ⚠️ 初学者常混淆：**16 位（RGB565）≠ 16 色**！16 位是 2^16 = 65536 种颜色（"16 位色"），16 色是 2^4 = 16 种。一个是直接色、一个是索引色，机制完全不同——做 BMP 解析时看到 biBitCount=16 和 biBitCount=4 别搞混。

## 5. 代码示例

示例 1：用 C 把"每像素位数"变成"显存/文件占用"。这里的行对齐公式来自 BMP 规范（下一课细讲），现在先感受"色深 → 字节数"的换算。

```c
/* 色深与内存占用换算（第 8 课：位图概念） */
#include <stdint.h>

#define SCREEN_W   320     /* 屏幕宽度（像素） */
#define SCREEN_H   240     /* 屏幕高度（像素） */

/* BMP 要求每行字节数是 4 的整倍数：先算出裸行字节数，再向上取整到 4 */
uint32_t bmp_line_bytes(uint32_t width, uint32_t bpp)
{
    uint32_t raw = (width * bpp + 7) / 8;   /* 裸行字节数 */
    return (raw + 3) & ~3u;                 /* 向上取整到 4 的倍数 */
}

/* 一屏显存（不按 BMP 对齐，直接算） */
uint32_t frame_bytes(uint32_t w, uint32_t h, uint32_t bpp)
{
    return w * h * bpp / 8;
}

/* 测试：打印各种色深下一屏 320×240 的占用 */
void demo_color_depth(void)
{
    const uint32_t w = SCREEN_W, h = SCREEN_H;

    printf("1 位(黑白)  : %u KB\n", frame_bytes(w, h, 1) / 1024);   /* 9 KB */
    printf("4 位(16色)  : %u KB\n", frame_bytes(w, h, 4) / 1024);   /* 37 KB */
    printf("8 位(256色) : %u KB\n", frame_bytes(w, h, 8) / 1024);   /* 75 KB */
    printf("16 位(565)  : %u KB\n", frame_bytes(w, h, 16) / 1024);  /* 150 KB */
    printf("24 位(真彩) : %u KB\n", frame_bytes(w, h, 24) / 1024);  /* 225 KB */
}
```

示例 2：24 位 RGB888 → 16 位 RGB565 转换。后面 0010 课解析 24 位 BMP 到 LCD 显示，核心就是这句。

```c
/* 24 位 RGB(每分量 8 位) → 16 位 RGB565 */
/* 原理：把 8 位分量的高位"浓缩"成 5/6/5 位，丢弃低位细节 */
uint16_t rgb888_to_565(uint8_t r, uint8_t g, uint8_t b)
{
    return ((uint16_t)(r & 0xF8) << 8) |   /* R: 取高5位, 放到 bit15~11 */
           ((uint16_t)(g & 0xFC) << 3) |   /* G: 取高6位, 放到 bit10~5  */
           (b >> 3);                        /* B: 取高5位, 放到 bit4~0   */
}

/* 验证：红色 255,0,0 → 0xF800（lcd.h 里 RED 宏就是这个值） */
uint16_t red = rgb888_to_565(255, 0, 0);    /* = 0xF800 ✓ */
```

> 💡 交叉验证：打开 `BSP/LCD/lcd.h`，看 `RED 0xF800`、`GREEN 0x07E0`、`BLUE 0x001F` 这些宏——正是上面公式的产物。你现在就能看懂驱动里颜色宏的来源了。

- A. 扫描时逐像素着色的设备
- B. 采用二维像素矩阵显示和存储图像的设备
- C. 只支持黑白两色的显示设备

<details><summary>查看答案</summary>

B。"位映象"指二维像素矩阵，位图就是用位映象方法显示和存储的图像（章节 1）。

**Q2. RGB 三通道各 8 位量化后，共能表示多少种颜色？**

- A. 256 种
- B. 65536 种
- C. 约 1600 万种

<details><summary>查看答案</summary>

C。256×256×256 ≈ 1600 万（章节 1），对人眼已经足够。

</details>

**Q3. 200×200 的 16 色图，用调色板方案存储约需多少字节？**

- A. 约 120KB，每像素 3 字节直接存 RGB
- B. 约 20KB，每像素 4 位存索引 + 48 字节调色板
- C. 约 20KB，每像素 4 位存 RGB 值

<details><summary>查看答案</summary>

B。16 色 = 4 位索引，200×200×0.5 ≈ 20KB，加 3×16=48 字节调色板表，约为直接存储的 1/6（章节 1）。

</details>

**Q4. 为什么 24 位真彩色图不用调色板？**

- A. 因为真彩色图的颜色数太少用不着
- B. 因为调色板技术只支持 16 种颜色
- C. 索引也要 24 位，和直接存 RGB 一样大，还得白搭一张巨型调色板

<details><summary>查看答案</summary>

C。2^24 种颜色需要 24 位索引，与直接存 RGB 字节数相同，无收益反增开销（章节 1）。

</details>
