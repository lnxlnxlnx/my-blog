# JPEG 原理：DCT 与量化

把图像从"像素世界"搬进"频率世界"，然后狠心扔掉你看不见的部分（ISO/IEC 10918-1 核心）

**本课目标：**JPEG 为什么能把照片压到十分之一还看不出差别？因为它是**有损压缩**——先把像素变成频域系数（DCT 离散余弦变换），再按"人眼敏感程度"分档丢弃（量化 quantization）。学完你能：画出 baseline 顺序模式编码流程、说清 4:2:0 下采样、解释"能量集中在左上角"、读懂量化表，并亲手写一个量化循环。（预计 45~50 分钟）

## 1. JPEG 是什么：有损压缩与 baseline 顺序模式

JPEG（ISO/IEC 10918-1）不是一种格式，而是一族编码流程（process）。最常用、所有解码器必须支持的是 **baseline（基线）顺序模式**（10918-1 §3.1.8）：

- **有损（lossy）**：解码结果和原图不完全一样，但人眼基本分不出来
- **顺序（sequential）**：从上到下、从左到右一块块处理，一次扫描搞定（区别于 progressive 渐进式的多次扫描）
- **8 位精度**：每个分量样本 0..255；**Huffman 熵编码**（下一课）；最多 4 个分量、2 张 DC 表 + 2 张 AC 表

标准里还有其他模式：SOF1 扩展顺序、SOF2 渐进（progressive）、SOF3 无损（lossless）、SOF9/10/11 算术编码版等（§B.1.1.2 标记表）。我们抓住 baseline 一条主线讲透，其他的都是"换零件"。

## 2. 编码流程总览：像素怎么变成一串比特

baseline 编码是条单向流水线，六个工序（§F.1.1.2）：

```text
像素世界                       频率世界                        码流
RGB ──► YCbCr ──► 8×8 分块 ──► DCT(时域→频域) ──► 量化(÷表取整)
                                        │              │
                                        ▼              ▼
                                  64 个系数         Zig-Zag 排序
                                  DC×1 + AC×63         │
                                                        ▼
                                           熵编码 (Huffman / 算术) ──► JPEG 码流

# 解码就是全程倒着走 (IDCT 逆变换、反量化 R=Sq×Q、+128 电平恢复)
```

本课讲前三板斧：色彩空间、8×8 分块 + DCT、量化。剩下的 Zig-Zag 与熵编码是第 14 课。

## 3. 色彩空间与 4:2:0 下采样：先删掉人眼不敏感的

RGB 三个通道的信息量一样多，但人眼不是"均匀传感器"——对**亮度（明暗变化）极敏感，对色度（颜色差异）迟钝得多**。JPEG 抓住这个弱点，第一步就把颜色拆开：

- **Y**：亮度（luminance），人眼主要靠它认轮廓
- **Cb / Cr**：两个色差（chrominance），人眼几乎分不清它的细节

```c
/* ===== YCbCr 色彩空间 (8 位量化版, 常用整系数近似) ===== */
/* JPEG 把 RGB 转成亮度 + 两个色差, 人眼对亮度最敏感 */
uint8_t r, g, b;                  /* 0..255 输入 */
int y  = ( 66 * r + 129 * g +  25 * b + 128) >> 8;   /* Y 亮度   */
int cb = (-38 * r -  74 * g + 112 * b + 128) >> 8;   /* Cb 色差1 */
int cr = (112 * r -  94 * g -  18 * b + 128) >> 8;   /* Cr 色差2 */
y  += 16; cb += 128; cr += 128;   /* 转到标准偏移量 */
```

既然人眼对色度细节不敏感，那就**少采点**。最常见的是 **4:2:0 下采样**：色度在水平、垂直方向各减半——每 4 个亮度样本（2×2）才配 1 个 Cb 和 1 个 Cr（§A.1.1 采样因子）。采样因子（sampling factor）H×V 写进帧头：Y=2×2，Cb=Cr=1×1。

一个 **MCU（minimum coded unit，最小编码单元）**，就是各分量按采样因子组成的最小循环块（§3.1.88）：4:2:0 时每个 MCU = **4 个 Y 块 + 1 个 Cb 块 + 1 个 Cr 块**，共 6 个 8×8 块。解码时色度块要被放大回去（插值），因为原本就丢了一半信息。

## 4. 8×8 分块与 DCT 原理：时域 → 频域

图像先切成一个个 **8×8 像素块**（block / data unit，§3.1.11），每个块独立处理。DCT 前还有一步 **电平平移（level shift）**：8 位样本 0..255 先减去 128 变成 -128..127 的有符号数（§F.1.1.3）：

```c
/* ===== 8×8 分块 + 电平平移 (10918-1 F.1.1.3) ===== */
#define SUB 128                     /* 8 位样本: 减 128 平移到有符号 */

int16_t blk[8][8];                  /* 一个 8×8 亮度块 */
for (int y = 0; y < 8; y++)
    for (int x = 0; x < 8; x++)
        blk[y][x] = (int16_t)Y(x, y) - SUB;   /* 0..255 → -128..127 */

/* 之后对 blk 做 FDCT, 得到 64 个系数 (1 个 DC + 63 个 AC) */
```

然后对每个块做 **FDCT（正向离散余弦变换）**，把 8×8 的"亮度分布"变成 8×8 的"频率分布"（§F.1.1.3、A.3.3）。输出的 64 个值叫 **DCT 系数（DCT coefficient）**：

- **DC 系数（直流）**：1 个，位置 (0,0)，代表整个块的平均亮度——能量大头
- **AC 系数（交流）**：63 个，位置越靠右下，代表越**高频**的细节纹理

🎯 关键洞察：**自然照片里相邻像素通常很接近**，所以能量集中在低频——变换后绝大多数系数要么很小、要么是 0。这正是压缩的突破口：DCT 不直接省字节，它把信息"归堆"到左上角，好让下一步量化放心地扔掉右下角。

## 5. 量化表：有损压缩真正下手的地方

量化（quantization）把每个 DCT 系数除以量化表里对应的步长，再取整（§A.3.4）：

```text
量化(编码):   Sq = round( S / Q )     // S 是 DCT 系数, Q 是表里对应步长
反量化(解码):  R  = Sq × Q             // 乘回去, 但四舍五入丢的信息补不回来
```

标准在 **Annex K 给出两张"典型"量化表**（§K.1），基于人眼心理视觉实验（psychovisual thresholding）得出——注意是**示例**，不是强制默认值。左上角小（细分低频，保护人眼敏感的）、右下角大（粗分高频，大胆丢）：

```text
亮度量化表 K.1              色度量化表 K.2
16 11 10 16 24 40 51 61     17 18 24 47 99 99 99 99
12 12 14 19 26 58 60 55     18 21 26 66 99 99 99 99
14 13 16 24 40 57 69 56     24 26 56 99 99 99 99 99
14 17 22 29 51 87 80 62     47 66 99 99 99 99 99 99
18 22 37 56 68 109 103 77   99 99 99 99 99 99 99 99
24 35 55 64 81 104 113 92   99 99 99 99 99 99 99 99
49 64 78 87 103 121 120 101 99 99 99 99 99 99 99 99
72 92 95 98 112 100 103 99  99 99 99 99 99 99 99 99
```

你会发现色度表里 99 满天飞——因为色度本来就没细节，直接粗暴量化，几乎全部系数变成 0，色度分量占的字节量微乎其微。编码端把这些值写进 **DQT（Define Quantization Table）段**。

量化循环写起来很直白（注意负数要就近取整，不能直接整除）：

```c
/* ===== 量化: Sq = round(S / Q) (10918-1 A.3.4) ===== */
/* 标准亮度量化表 K.1 (Annex K 的示例表, 行主序) */
static const uint8_t q_luma[64] = {
    16, 11, 10, 16, 24, 40, 51, 61,
    12, 12, 14, 19, 26, 58, 60, 55,
    14, 13, 16, 24, 40, 57, 69, 56,
    14, 17, 22, 29, 51, 87, 80, 62,
    18, 22, 37, 56, 68,109,103, 77,
    24, 35, 55, 64, 81,104,113, 92,
    49, 64, 78, 87,103,121,120,101,
    72, 92, 95, 98,112,100,103, 99,
};

static int round_div(int v, int d)          /* 就近取整的除法 */
{
    return (v >= 0) ? (v + d/2) / d : -((d/2 - v) / d);
}

int16_t s[64];      /* FDCT 输出 */
int16_t sq[64];     /* 量化结果 */
for (int k = 0; k < 64; k++)
    sq[k] = (int16_t)round_div(s[k], q_luma[k]);

/* 解码端反量化: R = Sq × Q (无损乘回去, 但取整信息已丢) */
int16_t r[64];
for (int k = 0; k < 64; k++)
    r[k] = (int16_t)(sq[k] * q_luma[k]);
```

**Q 因子（quality factor）**就是各种工具里的"质量滑块"：libjpeg 等实现把它换算成对整张表的缩放。Q 越小 → 表值越小 → 量化越细 → 保留的系数越多 → 文件越大、质量越高；Q 越大 → 表值越大 → 大量系数被取整成 0 → 文件越小、质量越低。它和"压缩率"是**一条反向曲线**上的两个端点。

> 💡 **为什么压缩能这么狠？**典型照片的 8×8 块做完 DCT+量化后，60~80% 的 AC 系数直接变成 0。下一课的 Zig-Zag + 游程编码就是专门"吃"这一串 0 的——把 64 个系数拉直后，后面会拖着一长串零，一个 EOB 标记就能收尾。

## 6. 解码方向：把世界再搬回来

解码就是把编码流程**整体倒着走**（§F.2、图 6）：熵解码 → 反 Zig-Zag 填回 8×8 → 反量化（R=Sq×Q）→ **IDCT（逆离散余弦变换）**把频域变回时域 → 加回 128 恢复电平 → YCbCr 插值放大 → 转回 RGB。有损就损在量化那一步：取整的误差永远补不回来，所以 IDCT 出来的是"近似原图"。

> ⚠️ **本课只讲了 baseline 的核心，别急着写解码器：**还有 Zig-Zag、差分 DC、AC 游程、Huffman 表构建、字节填充（0xFF 后补 0）这些细节没到。真正要落地，LVGL 的 SJPG / TJpgDec 库已经封装好（第 14 课末介绍）。先理解"DCT 归堆 + 量化丢弃"这个哲学，比背公式更重要。

## 动手练习（约 20 分钟）

### 练习 13.1：想通"为什么能量集中在左上角"

1. 拿一张纯色（全 128 灰度）的 8×8 块：它没有明暗变化，DCT 后除了 DC 系数，63 个 AC 系数会是多少？
2. 再拿一张左黑右白的"阶跃"块：变化只发生在水平方向，能量会集中在哪个频率轴上？
3. 用一阶理解回答：为什么照片 DCT 后低频系数普遍比高频大？这和"相邻像素接近"是什么关系？

### 练习 13.2：JPEG vs BMP 同图体积对比

1. 用同一张照片导出 4 个文件：BMP（无压缩）、JPEG 质量 95、JPEG 质量 70、JPEG 质量 30。
2. 记录 4 个文件大小，算一算 JPEG 相对 BMP 压缩了多少倍；肉眼对比质量 30 和 95 的差异。
3. 思考：质量 30 时文件还能小多少？把质量滑到 5 试试，观察"块效应"（blockiness）——这就是量化表值过大、AC 系数被砍光的代价。

### 随堂小测

**Q1. baseline 顺序模式中，8 位样本做 DCT 前要先做什么？**

- A. 减去 128 做电平平移，变有符号数
- B. 除以 255 归一化到 0..1 浮点
- C. 加上 128 再取绝对值
- D. 先转成 16 位再减 2048

<details><summary>查看答案</summary>

A。0..255 减 128 → -128..127（§F.1.1.3）。

</details>

**Q2. 一个 8×8 块做 DCT 后得到多少系数？其中 DC、AC 各几个？**

- A. 64 个：DC 1 个 + AC 63 个
- B. 8 个：DC 1 个 + AC 7 个
- C. 64 个：DC 32 个 + AC 32 个
- D. 63 个：全部都是 AC 系数

<details><summary>查看答案</summary>

A。64 个系数，左上角 (0,0) 是 DC（均值），其余 63 个 AC（§3.1.35、F.1.1.2）。

</details>

**Q3. 4:2:0 下采样里，色度信息相对亮度减到什么程度？**

- A. 每 2×2 亮度块对应 1 个 Cb 和 1 个 Cr
- B. 完全丢弃 Cb 和 Cr 两个分量
- C. 色度样本数比亮度还多 4 倍
- D. 色度与亮度样本数完全相同

<details><summary>查看答案</summary>

A。水平垂直各减半，4 个亮度配 1 个 Cb + 1 个 Cr（§A.1.1）。

</details>

**Q4. 量化表数值越大（比如 99），效果是？**

- A. 压缩率越高，图像质量越低
- B. 压缩率越低，图像质量越高
- C. 文件大小不变，质量也不变
- D. 只影响色度，不影响亮度

<details><summary>查看答案</summary>

A。步长越大，越多系数被取整成 0，文件越小、质量越差。

</details>
