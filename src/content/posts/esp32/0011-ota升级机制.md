# OTA 升级机制

这是 ESP-IDF 课程系列笔记的第 11 课(预计 15 分钟)。STM32 做 IAP 要自己写引导程序;ESP32 的 OTA 是**官方内置方案**:双分区 + 引导回滚。xiaozhi 连服务器第一步就是 OTA 握手(你现在服务器上那个 `/xiaozhi/ota/` 接口),所以这课是理解 xiaozhi 网络流程的必选项。

## 知识点 1:双分区原理

```csv
# 有两份 app 分区,新固件写"另一个"
ota_0, app, ota_0, 0x10000, 0x1f0000,
ota_1, app, ota_1, 0x200000, 0x1f0000,
```

流程:下载新固件 → 写进当前未用的 ota 分区 → `esp_ota_set_boot_partition` 指向它 → 重启。如果新固件起不来,**回滚保护**让它退回旧分区。这就是为什么 xiaozhi 的 `sdkconfig.defaults` 里开着 `CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE`。

## 知识点 2:esp_ota 核心 API

```c
esp_ota_begin(part, OTA_SIZE_UNKNOWN, &handle);   // 开始
esp_ota_write(handle, buf, len);                  // 流式写
esp_ota_end(handle);                             // 结束/校验
esp_ota_set_boot_partition(part);                // 切换启动
esp_restart();                                    // 重启
```

看 xiaozhi 的 `main/ota.cc`:第 336 行附近正是 `esp_ota_begin`,整个文件就是这套 API 的实战。

## 动手实践

打开 `xiaozhi-esp32-2.2.4/main/ota.cc` 读前 100 行:**画出手握 HTTP 下载 → 写分区 → 校验 → 重启 的流程**。再到 `basic_routines/36_bootloader` 看双 OTA 分区表和引导流程。

## 测验

### 测验 1
新固件起不来时靠什么回退?
- A. 回滚保护(正确)
- B. 看门狗
- C. 备份芯片

<details>
<summary>答案与解析</summary>

**答案：A**。Bootloader 回滚保护,验证失败自动退旧分区。
</details>

### 测验 2
设备开机先连服务器的什么接口?
- A. OTA(正确)
- B. WebSocket
- C. MQTT

<details>
<summary>答案与解析</summary>

**答案：A**。OTA 握手(/xiaozhi/ota/),拿配置和固件版本。
</details>
