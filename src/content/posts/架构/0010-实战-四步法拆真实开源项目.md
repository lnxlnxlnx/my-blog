# 实战:四步法拆真实开源项目

十课磨的剑,现在出鞘。我们用**第一课的四步法**,拆一个你天天用的真实项目——scikit-learn 的基类文件 `sklearn/base.py`。你会发现:里面全是这十课的模式,一个不落。

## 回顾:十课一张图

- **读法(0001)**:三个尺度 · 四步读法
- **地基(0002)**:接口与多态 ABC / Protocol
- **招式(0003-07)**:策略 · 工厂 · 适配器/门面 · 观察者 · 模板/装饰器
- **内功(0008-09)**:组合优于继承 · 依赖注入 · 分层 · 依赖方向

招式让「读得懂」,内功让「说得清、改得动」。现在把它们用在真项目上。

## 四步法拆 sklearn/base.py

文件在 [sklearn/base.py](https://github.com/scikit-learn/scikit-learn/blob/main/sklearn/base.py)(约 1100 行)。我们不逐行,只走四步。

### 第 1 步:找入口

入口不在文件里,而在**用法**上——每个模型都长一个样:

```python
from sklearn.linear_model import LogisticRegression

model = LogisticRegression()        # 入口:构造,统一接口
model.fit(X, y)                     # 入口:统一动作
model.predict(X); model.score(X, y) # 万变不离四件套
```

scikit-learn 的成功就靠这条「铁约定」:**每个估计器都有 fit / predict / score,参数用 get_params / set_params 读写**。这就是一个全生态共享的接口。

### 第 2 步:画依赖

BaseEstimator 不依赖任何具体模型——它给所有模型提供「默认行为」;**依赖方向是模型 → BaseEstimator**。具体模型怎么被复制?看 `clone()`——一个地地道道的**工厂函数**:

```python
# sklearn/base.py 真实代码(节选)
def clone(estimator, *, safe=True):
    """Construct a new unfitted estimator with the same parameters."""
    estimator_type = type(estimator)
    if estimator_type is dict:
        return {k: clone(v, safe=safe) for k, v in estimator.items()}
    ...
    klass = estimator.__class__                    # 靠 get_params 约定
    new_object_params = estimator.get_params(deep=False)
    ...
    new_object = klass(**new_object_params)        # 重新造一个,不复制训练结果
    return new_object
```

`clone` 认得「参数约定」(get_params),按名字重造对象——**工厂模式 + 注册表思想**,网格搜索 GridSearchCV 就靠它复制出无数份模型。

### 第 3 步:找抽象

BaseEstimator 本身不强迫继承,但约定处处是「抽象」。看两个最妙的:

```python
# sklearn/base.py · TransformerMixin:模板方法
class TransformerMixin:
    def fit_transform(self, X, y=None, **fit_params):
        # 骨架:先 fit 再 transform,顺序定死
        if y is None:
            return self.fit(X, **fit_params).transform(X)
        return self.fit(X, y, **fit_params).transform(X)
```

```python
# sklearn/base.py · _fit_context:装饰器(还带着 functools.wraps 保真)
@functools.wraps(fit_method)
def wrapper(estimator, *args, **kwargs):
    ...
    with config_context(...), callback_management_context(estimator):
        return fit_method(estimator, *args, **kwargs)
    return wrapper
```

看到了吗——**模板方法**(fit_transform 定骨架)、**装饰器**(_fit_context 包 fit 方法)都是你学过的。而 ClassifierMixin/RegressorMixin 这类 **Mixin**,就是把行为切碎、按需**组合**进类的「组合优于继承」实战。

### 第 4 步:看实现

要看具体实现,就找实现了约定的类,比如 `sklearn/linear_model/_logistic.py` 的 LogisticRegression。你现在读它的姿势:

1. 只看 `__init__`(参数有哪些)→ 可被 clone / get_params 认领
2. 只看 `fit / predict`(怎么工作)→ 业务细节在 `_solve`/`_loss` 之类的方法里
3. 其余统统跳过

这就是第一课说的「只在你需要改的地方深入」。十课之后,你已经具备这套姿势了。

## 行动清单:把「读得懂」变成「参与合作」

参与复杂项目合作的真实路径,就在 GitHub 上(GitHub 就是最大的社区):

1. **从文档开始**:找到你过敏捷的库(scikit-learn / pytorch),读它的 `CONTRIBUTING.md` / `Developer Guide`
2. **从「好啃」的 issue 开始**:标签 `good first issue`、`documentation`、`help wanted`——改文档也是合法规格贡献
3. **先读测试,再读实现**:测试教你怎么用,实现教你怎么写
4. **提交前先看别人的 PR**:维护者 review 的内容,就是大项目「规范」的活教材
5. **小步提交**:一次 PR 只做一件事,描述里说清「为什么」

你已经具备读懂它们的所有词汇——差的只是动手一次。

## 测验

### 测验 1
添加策略时该做什么?
- A. 再去改源上下文
- B. 把旧代码全删掉
- C. 复制代码来复用
- D. 新增类不改调用(正确)

<details>
<summary>答案与解析</summary>

**答案：D**。开闭原则:对扩展开放、对修改关闭——加策略 = 新增一个类注册进去,调用方不动。
</details>

### 测验 2
看到 make_xxx 是什么?
- A. 策略模式的过程
- B. 观察者的回调处
- C. 模板方法的骨架
- D. 工厂模式的入口(正确)

<details>
<summary>答案与解析</summary>

**答案：D**。make_/create_/build_ 开头的函数基本都是工厂:集中创建、按名取对象、可替换、可测。
</details>

### 测验 3
接口对不上用什么?
- A. 派个观察者监听
- B. 用门面简化入口
- C. 装饰器增强功能
- D. 适配器进行包装(正确)

<details>
<summary>答案与解析</summary>

**答案：D**。适配器 = 中间翻译层,把别人的接口翻译成你的接口;门面则是把复杂藏起来的简单入口。
</details>
