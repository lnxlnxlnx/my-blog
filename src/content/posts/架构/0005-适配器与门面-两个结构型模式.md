# 适配器与门面:两个结构型模式

前四课学了行为型(策略)和创建型(工厂)。这课学**结构型(Structural)**里两个最高频的:**适配器(Adapter)**管「接口对不上」,**门面(Facade)**管「东西太多太难用」。

## 知识点 1:适配器——接口对不上时的翻译官

真实世界天天遇到:你的代码调用 `model.score(x, y)`,但第三方库叫 `model.evaluate(x, y)`;你的代码期望 JSON 结构 A,第三方返回结构 B。**适配器就是在中间加一层,把别人的接口翻译成你要的接口。**

典型场景——两套训练 API,你想统一成一套:

```python
# 第三方库 A:方法名是 evaluate
class ThirdPartyModel:
    def evaluate(self, X, y):
        ...

# 你的代码统一只认 score(x, y) —— 接口对不上!
model.score(X, y)   # AttributeError

# 适配器:翻译一层
class ModelAdapter:
    def __init__(self, third_party_model):
        self._inner = third_party_model       # 组合:包一个别人的对象

    def score(self, X, y):                    # 提供你的接口
        return self._inner.evaluate(X, y)     # 内部转成别人的接口


adapted = ModelAdapter(ThirdPartyModel())
adapted.score(X, y)      # 你的代码一行不改,就能用第三方了
```

适配器的关键词:**组合(包一层对象)+ 接口翻译**。用途往往是一瞬间的(比如只为了接上某个库),用完可以删——它保护的是「你的代码的稳定性」。

## 知识点 2:门面——给复杂系统一个简单入口

你有一个子系统,内部有多种组件、有先后顺序、有配置细节。每次用都要记住这一大堆?**门面(Facade)提供一个「极简入口」,把内部的复杂度藏起来。**

```python
# 没有一个门面时,使用者要记住整个流程:
raw = load_raw("data.csv")
clean = clean_data(raw)
feat = extract_features(clean)
model = RandomForest(**best_params())
model.fit(feat, labels)
report = evaluate(model, feat, labels)
save_model(model, "model.pkl")
save_report(report, "report.json")

# 门面:`train_pipeline()` 把所有步骤吃进肚子里
def train_pipeline(data_path, out_dir):
    raw = load_raw(data_path)
    clean = clean_data(raw)
    feat = extract_features(clean)
    model = RandomForest(**best_params())
    model.fit(feat, labels_from(raw))
    report = evaluate(model, feat, labels_from(raw))
    save_model(model, f"{out_dir}/model.pkl")
    save_report(report, f"{out_dir}/report.json")
    return model, report


model, report = train_pipeline("data.csv", "./out")   # 使用方只记一行
```

你可能已经意识到:第一课的 `BaseTrainer.run(data)` 就是一个门面——把 preprocess/build/fit/evaluate 一串悄悄封装,调用方只需要 `run()`。门面让「外部看起来简单、内部想多复杂都行」。

## 知识点 3:适配器 vs 门面,一句话分清

- **适配器 Adapter**:把**别人的接口**翻译成**你的接口**。方向:接口不匹配才用。
- **门面 Facade**:给**你自己的复杂系统**开一个简单入口。方向:内部太复杂才用。

共同点:都靠「包一层」;不同点:**适配器是翻译,门面是简化**。适配器让「能接上」,门面让「好上手」。

## 知识点 4:AI 代码里它们长什么样

AI 生成的代码里,这两种模式出镜率极高,认出来就不慌了:

```python
# 1) AI 经常给「几个库的不统一」套适配器:
class UnifiedEmbedder:
    """统一 OpenAI / HuggingFace / 本地模型 三种 embedder 接口。"""
    def __init__(self, backend):
        self._backend = backend
    def embed(self, text):
        if hasattr(self._backend, "encode"):
            return self._backend.encode(text)        # HF 风格
        return self._backend.create_embedding(text)  # OpenAI 风格


# 2) AI 经常把「管道」封装成门面:
def summarize_document(path, model="gpt"):
    text = extract_text(path)          # 子步骤
    chunks = split(text)
    emb = UnifiedEmbedder(make_model(model)).embed(chunks)  # 另一子系统
    return rerank(emb)
```

现在你不仅读得懂,还能说出名字:「哦,这里包了一层适配器,把两个接口统一了」「这里是个门面,把整条管道藏起来了」——这就是参与讨论的词汇量。

## 测验

### 测验 1
适配器主要解决?
- A. 让接口相互匹配(正确)
- B. 集中对象的创建
- C. 缓存常用的结果
- D. 加速方法的调用

<details>
<summary>答案与解析</summary>

**答案：A**。适配器在中间加一层,把别人的接口翻译成你要的接口——让「接口对不上」的两个系统接上。
</details>

### 测验 2
门面模式提供的入口?
- A. 一组复杂接口
- B. 一堆具体的实现
- C. 一段默认的代码
- D. 一个简单的入口(正确)

<details>
<summary>答案与解析</summary>

**答案：D**。门面把复杂子系统的内部顺序与配置藏起来,只暴露一个极简入口(比如 train_pipeline)。
</details>

### 测验 3
两者共同的目标是?
- A. 提高运行的速度
- B. 降低使用复杂度(正确)
- C. 减少内存的占用
- D. 增强类型的安全

<details>
<summary>答案与解析</summary>

**答案：B**。都靠「包一层」让调用方更省心:适配器省去改接口、门面省去记流程。
</details>
