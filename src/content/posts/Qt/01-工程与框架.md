# 01 工程与系统框架

本章回答三个问题：**一个 App 的工程文件长什么样**、**App 如何被 systemui 桌面启动**、**App 之间如何通信**。

## 1. 工程结构（.pro / qml.qrc / main.cpp）

以最简单的 `template/`（App 空白模板）为例：

```
template/
├── template.pro       # 工程文件(qmake 用)
├── main.cpp           # C++ 入口(启动 QML 引擎)
├── main.qml           # 顶层窗口
├── AppMainBody.qml    # App 主界面(桌面加载的就是它)
├── qml.qrc            # 资源清单(哪些 QML/图片打包进程序)
└── icons/             # 图标
```

### template.pro

```pro
QT       += quick                     # 使用 Qt Quick(QML)
greaterThan(QT_MAJOR_VERSION, 4): QT += widgets   # Qt5 才加 widgets
TARGET = template                      # 生成的可执行文件名
TEMPLATE = app
CONFIG += c++11
SOURCES += main.cpp                    # C++ 源文件
HEADERS +=                             # C++ 头文件
RESOURCES += qml.qrc                   # 资源文件
include(../client/client.pri)          # 引入公共框架(后面讲)
INCLUDEPATH += ../client
```

**`.pro` 里的 `QT +=` 行就是"我要用哪些 Qt 模块"**。qt_dev 各 App 用到的模块：

| 模块 | 作用 | 用到它的 App |
|------|------|-------------|
| `quick` | QML 界面 | 几乎所有 |
| `multimedia` | 摄像头/音频/视频 | camera, music, player, audio |
| `network` | 网络(TCP/套接字) | iot_control, screenview, mytest |
| `remoteobjects` | 进程间通信(桌面框架) | systemui, 所有 App 的 client.pri |
| `virtualkeyboard` | 屏幕虚拟键盘 | mytest, notepad, settings |
| `svg` | SVG 矢量图 | iot_control, fluid_demo |
| `quickcontrols2` | Qt Quick Controls 2 组件库 | fluid_demo |
| `3dcore/3drender/3dinput` | Qt 3D | dashboard |
| `widgets` | 传统 Widgets 界面 | openhome, screenview |

> 内存小技巧：`QT +=` 决定链接哪些 `libQt5Xxx.so`，缺了就编译报错。板子 Qt 5.12.9 完整版都装了。

### main.cpp —— C++ 入口

```cpp
#include <QGuiApplication>
#include <QQmlApplicationEngine>
#include <QQmlContext>
#include "systemuicommonapiclient.h"     // 公共框架:与桌面通信

int main(int argc, char *argv[])
{
    QGuiApplication app(argc, argv);
    qmlRegisterType<SystemUICommonApiClient>("com.alientek.qmlcomponents", 1, 0,
                                              "SystemUICommonApiClient");
    QQmlApplicationEngine engine;
    engine.rootContext()->setContextProperty("appCurrtentDir",
                                             QCoreApplication::applicationDirPath());
    engine.load(QUrl(QStringLiteral("qrc:/main.qml")));   // 加载 QML
    return app.exec();                   // 进入事件循环
}
```

要点：
- `QGuiApplication`（无 widgets）或 `QApplication`（有 widgets）
- `qmlRegisterType<Xxx>("模块名",1,0,"类型名")` → QML 里就能 `import com.alientek.qmlcomponents 1.0` 然后 `Xxx {}`
- `engine.rootContext()->setContextProperty("名字", 对象指针)` → QML 里直接用这个名字
- `qrc:/main.qml` 指从资源文件加载

### qml.qrc —— 资源清单

```xml
<RCC>
    <qresource prefix="/">
        <file>main.qml</file>
        <file>AppMainBody.qml</file>
        <file>icons/xxx.png</file>
    </qresource>
</RCC>
```
编译后 QML 文件、图片都被**打包进可执行文件**（`qrc_qml.cpp`），程序里用 `qrc:/xxx.png` 访问。好处：单文件部署，不依赖外部文件。

## 2. main.qml —— 顶层窗口

所有 QML App 的 main.qml 结构几乎一样：

```qml
import QtQuick 2.12
import QtQuick.Window 2.12
import QtQuick.VirtualKeyboard 2.4        // 需要虚拟键盘的 App
import com.alientek.qmlcomponents 1.0

Window {
    visible: true
    width: Screen.desktopAvailableWidth     // 全屏
    height: Screen.desktopAvailableHeight
    id: window
    x: 0
    y: 0
    color: "transparent"

    Client { programmerName: "template" }   // 公共框架:与桌面通信+悬浮返回按钮

    InputPanel {                             // 虚拟键盘(可选)
        id: inputPanel
        z: 99
        width: window.width
        states: State { ... }                 // 弹出动画
    }
}
```

**`Client` 是关键**：它来自 `client/Client.qml`（公共框架），做了两件事：
1. 与 systemui 通信（收到"显示"命令就显示本窗口，收到"退出"就退出）
2. 画一个可拖动的**悬浮返回球**（点击回桌面）

## 3. AppMainBody —— App 的真正入口界面

桌面启动 App 后，`Client` 内部会实例化 `AppMainBody.qml`（这是约定：**每个 App 必须有 AppMainBody.qml**）：

```qml
Item {
    anchors.fill: parent
    property real scaleFactor: window.width / 1024   // 按屏幕宽度缩放

    Loader {           // 动态加载实际界面
        active: true
        asynchronous: true
        anchors.fill: parent
        source: "MainLayout.qml"    // 实际界面文件
    }
}
```

## 4. 桌面框架（systemui）与 remoteobjects

### 4.1 三进程协作

```
┌──────────────┐  QtRemoteObjects  ┌──────────────┐
│  systemui    │◄─────────────────►│   App 进程    │
│ (桌面/窗口管理)│  local:interfaces │ (camera/led…) │
└──────────────┘                    └──────────────┘
```

- **systemui** 是服务端（`server/systemuicommonapiserver.cpp`），注册了 `SystemUICommonApi` 接口
- **每个 App** 通过 `client/systemuicommonapiclient.cpp` 连接同一个接口

### 4.2 接口定义（Repcs/systemuicommonapi.rep）

```
class SystemUICommonApi
{
    SIGNAL(serverSendVariant(const QByteArray &ba))   // 服务端 -> 客户端
    SLOT(void onServerVariant(const QByteArray &ba))  // 客户端 -> 服务端
}
```
Qt RemoteObjects 根据 `.rep` 生成 `replica`（客户端）和 `source`（服务端），两端通过 `QByteArray` 传**序列化的消息字典**（键值对：appName、appState、command…）。

### 4.3 App 如何让桌面隐藏自己

`client/Client.qml` 中：

```qml
SystemUICommonApiClient {
    id: systemUICommonApiClient
    appName: programmerName
    onActionCommand: {
        if (cmd === SystemUICommonApiClient.Show) {
            // 桌面要显示了 -> 请求桌面把自己藏起来
            systemUICommonApiClient.askSystemUItohideOrShow(SystemUICommonApiClient.Hide)
            appMainBody.visible = true
            window.show()
        }
        if (cmd === SystemUICommonApiClient.Quit)
            Qt.quit()
    }
}
```

流程：**桌面点击图标 → systemui 启动 App 进程 → App 回报"Active" → systemui 隐藏桌面 → App 显示**。这就是为什么从桌面进入 App 时桌面会"缩回去"。

### 4.4 桌面 cfg 文件（App 列表）

systemui 从 `/opt/ui/src/ATK-IMX6U/apk1.cfg` 等文件读 App 列表，每行：
```
appicons/puzzle.png 游戏 mytest
```
格式：`图标路径 显示名 程序名`。程序名对应 `/opt/ui/src/apps/<程序名>` 可执行文件。想给桌面加 App，就把二进制放进 `apps/` 并在 cfg 加一行。

## 5. 编译与部署

```bash
# 交叉编译(在 PC 上)
source /opt/fsl-imx-x11/4.1.15-2.1.0/environment-setup-cortexa7hf-neon-poky-linux-gnueabi
cd qt_dev/template
qmake template.pro
make -j16

# 传输到板子(本仓库脚本)
python3 my_code/appflash.py transfer qt_dev/template/template /opt/ui/src/apps/template
```

板端运行环境变量（`/etc/profile` 已设）：
```bash
export QT_QPA_PLATFORM=linuxfb:tty=/dev/fb0   # 用 framebuffer 显示
export QT_QPA_FB_TSLIB=1                        # 启用 tslib 触摸屏
export TSLIB_TSDEVICE=/dev/input/event1        # 触摸屏设备
export QT_QPA_FONTDIR=/usr/share/fonts/ttf     # 字体目录
```
