# 模块与垂直切片

这是 DDD 与六边形架构系列课程笔记的第 2 课，预计 20 分钟。上一课说了「每层放什么」。但还有个更重要的问题：**按什么把代码切开？** 项目用**模块(module)**组织——每个模块代表业务里的一个有界语境(bounded context)，模块内部再按「一个用例一个文件夹」切(垂直切片 Vertical Slicing)。本课讲清模块化思维与如何避免耦合。

## 知识点 1:按业务领域分模块,而非按技术分

反面写法(按技术类别堆一起，改一个功能要跨 N 个目录)：

```python
# 坏:all in one / 按技术层分
#   /controllers/user.py  /controllers/wallet.py
#   /services/user.py     /services/wallet.py
#   /models/user.py       /models/wallet.py
```

项目的做法：按业务概念分模块，每模块自带它的层次：

```python
# 好:按业务领域分模块
#   /modules/user/    (domain / application / interface / infrastructure)
#   /modules/wallet/
#   /modules/order/
```

好处是「一起变更的代码就近放着」；模块间少有依赖。这是 [高内聚](https://en.wikipedia.org/wiki/Cohesion_(computer_science))、[低耦合](https://en.wikipedia.org/wiki/Coupling_(computer_programming))的具体体现。

## 知识点 2:垂直切片——一个用例一个文件夹

模块内部，每个**业务用例(use case)**一个文件夹，把「这个用例需要的命令/服务/控制器」放一起，叫垂直切片：

```python
# modules/user/
#   commands/
#     create-user/        ← 一个用例一文件夹
#       create-user.command.py
#       create-user.service.py
#       create-user.controller.py
#     update-user/
#   queries/
#     find-users/
```

对照：项目里的 `src/modules/user/commands` 就是「user 模块的命令目录」，每个用例一个切面。读懂大项目时，先顺着一个用例的目录一路看下去，比横着扫一堆 service 文件清楚得多。

## 知识点 3:模块之间怎么少耦合(项目给的招)

直接 `import SomeClass from other_module` 会造成紧耦合。项目建议三招：

```python
# 1 抽公共:把共享逻辑放到独立文件,两边都依赖它,而不是互相依赖
#   shared/  (两模块都 import shared,不 import 彼此)
# 2 通过门面/中介者接触:模块只暴露公开门面 facade,隐藏内部私有
#   user_public.py  (module 公开接口)
# 3 用消息通信:命令总线命令、订阅对方发的事件(后面 0006 讲)
#   (commands bus / domain events)
```

记忆：**能靠「共同依赖」就别直接依赖**；模块之间通信尽量走公开接口或消息。

## 知识点 4:为什么要这样——方便拆微服务 + 好重写

如果每个模块的边界(bounded context)切得对，将来可以把某个模块单独拆成微服务，不用动领域逻辑(Greg Young 的 [The art of destroying software](https://youtu.be/Ed94CfxgsCA) 也讲：模块要小到能几天重写)。这就是「一个模块一个小应用」。

## 知识点 5:什么时候不要模块化过度

别为一个简单的增删改查硬切一堆模块和 facade。项目和你说的一样：**推荐而非铁律**，根据项目复杂度和规模取用。「模块要小、能重写」≠「什么都拆」。对小项目，一个模块、甚至单层脚本反而更合适。

## 测验

### 测验 1
项目按什么组织代码?
- A. 按技术类型
- B. 按业务领域(正确)
- C. 按文件大小
- D. 按版本号

<details>
<summary>答案与解析</summary>

**答案：B**。按业务领域分模块，每模块自带 domain/application/interface/infrastructure。
</details>

### 测验 2
一个用例一个文件夹叫什么?
- A. 单体
- B. 垂直切片(正确)
- C. 水平切片
- D. 金字塔

<details>
<summary>答案与解析</summary>

**答案：B**。每个业务用例一个文件夹(含其命令/服务/控制器)，叫垂直切片 Vertical Slicing。
</details>

### 测验 3
模块想避免耦合，首选?
- A. 直接 import 对方
- B. 抽公共依赖(正确)
- C. 复制粘贴
- D. 全局变量

<details>
<summary>答案与解析</summary>

**答案：B**。把共享逻辑抽到公共文件让两边都依赖它，而不是互相 import。
</details>

### 测验 4
模块切得好，将来可变成?
- A. 一个进程
- B. 独立微服务(正确)
- C. 一个文件
- D. 一个循环

<details>
<summary>答案与解析</summary>

**答案：B**。边界切对的模块可单独拆成微服务，不用动领域逻辑。
</details>
