# 值对象与领域不变量

这是 DDD 与六边形架构系列课程笔记的第 4 课，预计 25 分钟。上一课预告了**值对象(Value Object)**：没身份、不可变、按内容相等的「值」。项目特别强调用值对象替换裸字符串/数字(*primitive obsession 基本类型执念*)，让「非法状态不可表示」(make illegal states unrepresentable)。本课用 Python 讲透。

## 知识点 1:值对象长什么样

没 id、不可变、`==` 比较的是内容。用项目里的 Email / Address 做例子：

```python
class Email:                        # 值对象:包装一个"邮箱"
    def __init__(self, value: str):
        if "@" not in value:        # 构造即校验
            raise ValueError(f"非法邮箱: {value}")
        self._value = value
    @property
    def value(self):
        return self._value
    def __eq__(self, other):        # 按内容相等,不看身份
        return isinstance(other, Email) and self._value == other._value
    def __hash__(self):
        return hash(self._value)

a = Email("a@x.com")
b = Email("a@x.com")
print(a == b)        # True:内容一样就相等(值对象没有身份)
# a._value = "..."   # 不要:值对象应不可变(靠约定+不提供 setter)
```

对比实体：值对象没有唯一 id，相等看内容。[value object](https://martinfowler.com/bliki/ValueObject.html) 的经典定义。

## 知识点 2:为什么——把「校验」收进对象，取到的就合法

项目的话：如果每个参数的返回都是「合法值对象」，那么**每个方法天然有输入输出校验**，不用到处又 validate 一遍。把未经校验的裸字符串全线堵在门外：

```python
class User:
    def __init__(self, user_id: str, email: Email):   # 参数已是 Email 值对象
        self.id = user_id
        self.email = email                            # 拿到的一定是合法邮箱
```

因为**只有能构造出 Email 才传得进来**，非法邮箱在构造 Email 那一步就被拒了。这就是「非法状态不可表示」。

## 知识点 3:领域不变量(domain invariants)——永远为真的规则

**不变量** = 该领域里总得为真的条件，由实体/聚合根强制。例子：钱包余额≥0、不能是负；订购数量必须是正整数；买的东西必须库存足够。上上节课的 Wallet.debit 里「余额不足抛错」就是不变量([invariant](https://en.wikipedia.org/wiki/Class_invariant))。

## 知识点 4:用值对象做「领域原语」(domain primitive)

把业务里的单个基本值(邮箱、金额、距离)包成值对象，叫*领域原语*。它强制不变量、把行为集中一处、让代码用「业务词」而不是生硬 string/int([primitive obsession](https://refactoring.guru/smells/primitive-obsession))。例：钱别用 int，用 Money：

```python
class Money:
    def __init__(self, amount: int):
        if amount < 0:
            raise ValueError("金额不能为负")
        self._amount = amount
    @property
    def amount(self):
        return self._amount
    def add(self, other):            # 业务操作也封装在这里
        return Money(self._amount + other._amount)
```

这样「转账金额不能为负」这类规则被钉死在 Money 里，不会被各处散落代码绕过。

## 知识点 5:什么时候别过度

项目自己也提醒：**不是每个 string/int 都值得包成类**。给每个基本值建对象可能过度设计(尤其在 Python/TS 这类语言开销不小)。做法：仅为**有规则或行为的那些值**(邮箱格式、金额、账户号)建值对象，其余用普通类型 + 在领域外校验即可。判断：造了这个类是否减少处处重复的校验/带来明确语义？

## 测验

### 测验 1
值对象的相等性看什么?
- A. 身份 id
- B. 内容值(正确)
- C. 内存地址
- D. 创建顺序

<details>
<summary>答案与解析</summary>

**答案：B**。值对象没身份，相等看内容(结构相等)；实体才看 id。
</details>

### 测验 2
值对象应当是?
- A. 可变
- B. 不可变(正确)
- C. 可为空
- D. 带身份

<details>
<summary>答案与解析</summary>

**答案：B**。值对象不可变、无身份、按内容相等；通常构造时就把校验做了。
</details>

### 测验 3
把邮箱那类基本值包成类，叫?
- A. 实体原语
- B. 领域原语(正确)
- C. 控制器对象
- D. 服务对象

<details>
<summary>答案与解析</summary>

**答案：B**。domain primitive：把有规则/行为的单值包成值对象，构造即校验。
</details>

### 测验 4
「余额不能为负」属于?
- A. 临时约束
- B. 领域不变量(正确)
- C. UI 校验
- D. 优化目标

<details>
<summary>答案与解析</summary>

**答案：B**。invariant：该领域永远为真的规则，由实体/值对象强制，贯穿整个生命周期。
</details>
