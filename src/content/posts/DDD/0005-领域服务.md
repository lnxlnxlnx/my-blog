# 领域服务 Domain Service

这是 DDD 与六边形架构系列课程笔记的第 5 课，预计 20 分钟。Eric Evans 的定义：领域服务用于「一个不是单个实体或值对象自然职责的过程或变换」。也就是说——有段业务逻辑，**放哪个实体都不合适**(它要协调两个以上的实体/聚合)，就抽成一个**领域服务**。本课把「领域服务」和「应用服务」这两个容易混的东西彻底分清。

## 知识点 1:什么时候需要领域服务

当一个操作涉及多个实体、又不想让其中任何一个「知道太多/管别人的事」时，逻辑就放领域服务。典型的：转账需要「从 A 账户扣钱、给 B 账户加钱」，让 A 或 B 谁来做都不公平：

```python
class TransferService:                     # 领域服务
    @staticmethod
    def transfer(src: Wallet, dst: Wallet, amount: Money):
        src.debit(amount)                  # 各实体只做自己的事
        dst.credit(amount)
```

要点：领域服务只操作**领域类型**(实体/值对象)，不含外部技术细节；它把「牵涉多个实体」的业务过程集中一处，又不破坏封装。

## 知识点 2:领域服务 vs 应用服务(最容易混)

两个名字像，但层次完全不同：

```python
# 领域服务:在领域层,协调实体,全是业务规则,不碰外部/数据库
#   TransferService.transfer(src, dst, amount)

# 应用服务:在应用层,编排「一个用例」,调领域对象 + 通过端口取/存数据
#   CreateUserService.handle(command):
#       user = User(...)          # 造领域对象
#       repo.save(user)           # 通过端口存库(基础设施)
#       emit_event(...)           # 通过端口发事件
```

一句话：**领域服务处理"跨实体"的业务规则；应用服务编排"一个用户请求"的完整流程(含存库/发事件)**。项目里 user 模块的 create-user.service.ts 是应用服务；整个 DDD 里把"转账"这种跨 Wallet 的逻辑设为领域服务。

## 知识点 3:领域服务很"细"，应用服务是"门面"

项目(源自 Evans)说：领域服务**很粒度小**，是某个明确领域概念上的操作；应用服务则是给外部世界的**门面/API**，把多个领域操作串成完整用例。一个用例通常一个应用服务；领域服务更像领域内的"工具箱"。

## 知识点 4:判断逻辑该不该放领域服务

放实体/值对象 **vs** 放领域服务，判断：

```python
# 适合放实体内部:只跟自身状态有关的方法
#   Wallet.debit(amount)   # 只改自己 balance

# 适合放领域服务:需要协调多个实体,或放任何单个实体里都别扭
#   TransferService.transfer(a, b, amount)   # 牵涉两个账户

# 不适合放领域服务:需要访问数据库/外部API → 那是应用服务或端口的事
#   (领域服务只碰领域类型,不碰数据库!)
```

守则：领域服务**不 import 数据库、不发 HTTP、只操作领域对象**。「需要外部资源」的那层交给应用服务/端口(0007/0008)。

## 知识点 5:别滥用

优先级：先试着把逻辑放进一个实体；真要跨实体、放哪都别扭，才上领域服务。如果发现领域服务里全是"掩盖贫血实体"的代码，那问题在实体上(业务逻辑应该回到实体)。领域服务是补充，不是兜底垃圾场。

## 测验

### 测验 1
跨多个实体的业务逻辑放哪?
- A. 数据库
- B. 领域服务(正确)
- C. 控制器
- D. 端口

<details>
<summary>答案与解析</summary>

**答案：B**。协调多个实体的业务过程放领域服务，避免任一实体管别人的事。
</details>

### 测验 2
领域服务操作的对象类型?
- A. 数据库行
- B. 领域类型(正确)
- C. HTTP 响应
- D. DTO 传输

<details>
<summary>答案与解析</summary>

**答案：B**。领域服务只操作领域类型(实体/值对象)，不碰数据库/外部API。
</details>

### 测验 3
「一个用户请求完整流程」由谁编排?
- A. 领域服务
- B. 应用服务(正确)
- C. 值对象
- D. 元类

<details>
<summary>答案与解析</summary>

**答案：B**。应用服务编排完整用例(含调领域对象、经端口存库/发事件)，是外部世界的门面。
</details>

### 测验 4
出现大量"掩盖贫血实体"的领域服务，说明?
- A. 服务太少
- B. 实体该有方法(正确)
- C. 数据库该改
- D. 端口太多

<details>
<summary>答案与解析</summary>

**答案：B**。业务逻辑应回到实体，而不是全靠领域服务兜底。
</details>
