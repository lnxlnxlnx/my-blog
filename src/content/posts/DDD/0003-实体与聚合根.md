# 实体 Entity 与聚合根 Aggregate

这是 DDD 与六边形架构系列课程笔记的第 3 课，预计 25 分钟。领域层第一个积木是**实体(Entity)**：有身份、生命周期里身份不变、能保护自己**不变量**的业务对象。再往上，把「一组要一致变更的领域对象」包在一个根下，它就是**聚合(Aggregate)**。本课全用 Python 讲。

## 知识点 1:实体 = 有身份 + 业务逻辑,不只是数据结构

实体(User、Product、Order)有唯一 id，相等性看 id；**关键：业务逻辑放实体上**，不能有空的只存字段的贫血模型([Anemic Domain Model](https://martinfowler.com/bliki/AnemicDomainModel.html))。用项目里 wallet 实体做例子：

```python
class Wallet:
    def __init__(self, wallet_id: str, balance: int):
        self.id = wallet_id
        self.balance = balance

    def credit(self, amount: int):      # 业务方法:入账
        if amount <= 0:
            raise ValueError("金额必须为正")
        self.balance += amount

    def debit(self, amount: int):      # 业务方法:出账(保护不变量)
        if amount <= 0:
            raise ValueError("金额必须为正")
        if amount > self.balance:
            raise ValueError("余额不足")   # ← 不变量:不能为负
        self.balance -= amount
```

注意：没有公开 setter 让人随便改 balance；所有改变都走 `credit`/`debit`，在这两个方法里做校验。这就是「实体保护自己的不变量」。

## 知识点 2:构造时就要合法——fail fast

实体在**创建时就该合法**。别写无参构造再慢慢 set；把必填都收进构造函数校验，不合格直接抛错(快速失败 fail fast)：

```python
class User:
    def __init__(self, user_id: str, email: str):
        if "@" not in email:
            raise ValueError(f"非法邮箱: {email}")
        self.id = user_id          # 创建后不可变
        self.email = email
        self.wallet_id = None      # 可选,后续关联

    def attach_wallet(self, wallet_id: str):
        self.wallet_id = wallet_id
```

这些「保证对象永远正确」的规则，就是 [不变量 invariants](https://en.wikipedia.org/wiki/Class_invariant)——实体存在的前提。

## 知识点 3:值对象(预告)vs 实体

对比一下，方便你记：实体有 id、可变；**值对象**没 id、不可变、按内容相等。营销邮箱、金额、地址这类"只是一组值"的东西通常是值对象(下一课细讲)。实体 vs 值对象是 DDD 最先要分清的两种对象。

## 知识点 4:聚合根——一整组要一起变的对象的大门

**聚合(Aggregate)**是把多个实体/值对象包成一个边界，只通过一个**聚合根(Aggregate Root)**访问。聚合根是外界能直接拿到的唯一入口；聚合内的一致性由根保证。项目里 user 聚合根：

```python
class User:                     # 项目里 user.entity.ts 即聚合根(一个实体当根)
    def __init__(self, user_id, email):
        self.id = user_id
        self.email = email
        self.wallet = None      # 聚合内部可含其他对象(如钱包)

    def create_wallet(self, initial_balance: int):
        # 聚合根协调内部对象,保证一致性
        self.wallet = Wallet(wallet_id=new_uuid(), balance=initial_balance)
```

规则：外界对聚合的一切操作都**只能走聚合根**，不能跳过根直接摸内部成员([Aggregate](https://martinfowler.com/bliki/DDD_Aggregate.html))。

## 知识点 5:聚合的几条铁律

- 聚合根有**全局身份**(UUID/PK)；聚合内实体只有局部身份
- 聚合内一致性：改任一对象，整个聚合的不变量都要成立(一致性边界)
- 对聚合的操作是**事务性**的：要么全成要么全不做
- 聚合根可与别的聚合根用「id 引用」而非直接对象引用
- 聚合能发布**领域事件**(0006 讲)——这是解耦的关键

## 测验

### 测验 1
实体的相等性看什么?
- A. 所有字段值
- B. 它的身份 id(正确)
- C. 内存地址
- D. 创建时间

<details>
<summary>答案与解析</summary>

**答案：B**。实体有身份，相等性由 id 决定，生命周期里 id 不变。
</details>

### 测验 2
业务逻辑应放哪?
- A. 服务里全包
- B. 实体方法里(正确)
- C. 控制器里
- D. 数据库里

<details>
<summary>答案与解析</summary>

**答案：B**。业务逻辑放实体方法上，否则变贫血模型。服务只做编排。
</details>

### 测验 3
聚合外界只能访问谁?
- A. 内部任意成员
- B. 聚合根(正确)
- C. 值对象直接
- D. 没有限制

<details>
<summary>答案与解析</summary>

**答案：B**。对聚合的一切操作只能走聚合根这一个入口，保证一致性和不变量。
</details>

### 测验 4
对聚合的操作必须是?
- A. 可部分保存
- B. 事务性(全有或全无)(正确)
- C. 任意顺序
- D. 异步完成

<details>
<summary>答案与解析</summary>

**答案：B**。聚合内变更要么全保存要么全不保存，保证一致性边界不破裂。
</details>
