# 多线程与并发 threading / concurrent.futures

C 里线程很麻烦(pthread_create,手动互斥锁)。Python 提供了两档:底层 `threading.Thread` 自己管线程和锁;**现代推荐 `concurrent.futures`**——把「派一堆任务」「收集结果」封装好,几行搞定。本课先给最实用的 futures,再说 threading 与锁。

## 先记一句重要的:Python 线程的真相

Python 有 **GIL(全局解释器锁)**,同一时刻只有一个线程在执行 Python 字节码。**计算密集任务用线程不会变快**(C 程序员常幻想多线程=快)。但 **IO 密集任务(网络、磁盘、睡眠)用线程/异步能大幅提速**。所以:烧 CPU 用多进程(ProcessPoolExecutor),等 IO 用多线程/异步。

## 知识点 1:concurrent.futures ThreadPoolExecutor——最省心的并发

想「并发的做一堆 IO 任务」,用 `ThreadPoolExecutor.map` 或 `submit`,几行完事:

```python
from concurrent.futures import ThreadPoolExecutor
import time

def fetch(url):
    time.sleep(1)          # 假装是网络请求
    return f"OK {url}"

urls = [f"http://site/{i}" for i in range(5)]

# map:把 fetch 依次应用到每个 url,并行的跑
with ThreadPoolExecutor(max_workers=4) as ex:
    results = list(ex.map(fetch, urls))
print(results)
# 5 个各睡 1 秒,4 个 worker 并发 ≈ 2 秒完成,而不是 5 秒
```

`ThreadPoolExecutor(max_workers=n)` 建一个线程池,`ex.map(f, list)` 并行地把 f 作用到每个元素、按序收集结果。`with` 会自动等全部完成并清理。

## 知识点 2:submit / as_completed——拿到每个结果,先完成的先处理

`map` 按输入顺序给结果;`submit` 返回 future,配合 `as_completed` 谁先完成谁先被处理(适合耗时不均):

```python
from concurrent.futures import ThreadPoolExecutor, as_completed
import time

def job(i):
    time.sleep((5 - i) * 0.2)   # job 0 最慢
    return i

with ThreadPoolExecutor(max_workers=3) as ex:
    futures = {ex.submit(job, i): i for i in range(5)}
    for fut in as_completed(futures):
        print(fut.result())    # 先完成的先打印:4,3,2,1,0
```

`fut.result()` 拿到返回值;任务里抛异常会在这里抛出。`as_completed` 按完成顺序 yield future。

## 知识点 3:烧 CPU 的任务用 ProcessPoolExecutor

计算密集(如大量浮点运算)线程被 GIL 卡住变不快,**改用 `ProcessPoolExecutor`**,用多进程绕过 GIL(注意:开销更大,任务要能入队、不能传太复杂的对象):

```python
from concurrent.futures import ProcessPoolExecutor

def heavy(n):
    return sum(i * i for i in range(n))

if __name__ == "__main__":      # 多进程必须套这个
    with ProcessPoolExecutor(max_workers=4) as ex:
        res = list(ex.map(heavy, [1_000_000] * 4))
    print(res)
```

`ProcessPoolExecutor` 用法和线程池一样,只是内核不同;多进程代码要放 `if __name__ == "__main__"` 里(上一课学过)。

## 知识点 4:底层 threading.Thread 与 join

要自己起一个单独线程跑一段任务,用 `threading.Thread`,`.start()` 启动、`.join()` 等它结束:

```python
import threading, time

def worker(name):
    print(f"开始 {name}")
    time.sleep(1)
    print(f"结束 {name}")

t = threading.Thread(target=worker, args=("A",))
t.start()          # 在后台线程跑
t.join()           # 主线程等 t 结束再继续
print("完毕")
```

什么时候手写 Thread?少数情况(需要 long-running 后台线程、精细控制)。多数「跑一批返回结果」的任务,futures 更省心。

## 知识点 5:共享数据与锁(进阶,先了解)

多个线程改同一个变量会有竞态;要保护共享数据用 `threading.Lock`:

```python
import threading

lock = threading.Lock()
counter = 0

def inc():
    global counter
    for _ in range(1000):
        with lock:          # 进入锁,保护临界区
            counter += 1

threads = [threading.Thread(target=inc) for _ in range(10)]
for t in threads: t.start()
for t in threads: t.join()
print(counter)   # 应该 10000;没锁可能 < 10000
```

`with lock:` 是带着锁的缩进块,像 with 文件一样自动释放。**尽量避免共享可变状态**(futures 的 map/submit 天然避免)比加锁更好。
