# 模块与包:组织代码

C/C++ 里代码靠头文件 + 链接组织。Python 用**模块(module)**(一个 .py 文件)和**包(package)**(带 `__init__.py` 的目录)组织代码,用 `import` 引用。本课让你理解「import 到底做了什么」、怎么写一个清晰的包、以及常见坑。

## 知识点 1:模块 = 一个 .py 文件,import 即执行

每个 .py 文件是一个模块。用 `import` 引入时,**文件会被执行一次**,里面定义的函数/变量/类成为模块的属性,用 `模块名.名字` 访问:

```python
import math            # 引入 math 模块(标准库)
math.sqrt(9)           # 3.0:用 模块.函数

from math import sqrt   # 只引入某个名字
sqrt(9)                 # 直接用(少了 math. 前缀)

from math import pi, e  # 一次引多个
# 别名
import numpy as np      # 长模块名用别名(惯例)
```

三种方式:`import m` / `from m import x` / `import m as alias`。用 `from m import *` 会污染命名空间,**尽量避免**。

## 知识点 2:import 的查找路径(sys.path)与「执行一次」

`import m` 会按 `sys.path` 里的目录逐个找叫 `m.py`(或包)的文件,找到就加载;**同一个模块在整个进程里只执行一次**(之后的 import 是缓存命中):

```python
import sys
print(sys.path)   # 搜索路径列表:当前目录、标准库、site-packages 等

# 模块只执行一次:重复 import 不会重复跑顶层代码
import math
import math       # 不会再执行 math 模块内容
```

有序 sys.path:通常第一个是「当前脚本所在目录」(或 cwd),所以同级 .py 能被直接 import。想查某模块在哪:`print(module.__file__)`。

## 知识点 3:包 = 带 __init__.py 的目录;为什么要 __init__.py

目录要成为「包」、能 `import`,传统上要有个 `__init__.py`(空的一代也行)。包把多个模块组织成层级:

```python
# 目录结构:
# myapp/
#   __init__.py
#   utils.py
#   models/
#       __init__.py
#       user.py
#
# 引入方式:
import myapp.utils            # 包.模块
from myapp.models import user
from myapp.models.user import User   # 包.模块.名字
```

`__init__.py` 在「import 这个包」的时候执行,常用来做「包的公开接口」:`from myapp import User` 之所以能用,是因为 `myapp/__init__.py` 里写了 `from .models.user import User`。

## 知识点 4:相对导入 vs 绝对导入

包内部模块互相引用:**推荐绝对导入** `from myapp.utils import clean`;相对导入用 `.` / `..`(当前包/上级包):

```python
# 在 myapp/models/user.py 里想用 utils.clean
from myapp.utils import clean        # 绝对导入(推荐,清晰)

# 或相对导入
from ..utils import clean            # .. = 上一级包 myapp
```

绝对导入更清晰、可读、不易错;半路转相对容易引混乱。脚本(顶层入口)里避免相对导入(它们需要包上下文)。

## 知识点 5:别把「可执行代码」塞进被 import 的模块——用 __name__ 保护

你在 0012 学过 `if __name__ == "__main__"`。这在此特别重要:被 import 的模块一旦顶层有 print/测试代码,import 时就会执行。把「只有直接运行才跑」的部分放 __main__ 判断里:

```python
# utils.py
def clean(s):
    return s.strip().lower()

if __name__ == "__main__":
    # 这段只有: python utils.py 才跑;被 import 时不跑
    print(clean("  HI  "))
```

这样别人 import utils 不会触发你的测试输出。这是「可 import 又可直接运行」的标准写清。

## 测验

### 测验 1
import m 会怎样?
- A. 只编译不执行
- B. 执行模块一次(正确)
- C. 复制代码进来
- D. 执行多次

<details>
<summary>答案与解析</summary>

**答案：B**。import 会执行该模块文件一次;同一模块进程内只执行一次。
</details>

### 测验 2
目录要成为可 import 的包,需要?
- A. 一个 .py 必写
- B. __init__.py(正确)
- C. setup.py
- D. MANIFEST

<details>
<summary>答案与解析</summary>

**答案：B**。目录带 __init__.py 才是包;它常在 import 包时执行、暴露公开接口。
</details>

### 测验 3
包内推荐用哪种导入?
- A. 相对导入
- B. 绝对导入(正确)
- C. * 星号导入
- D. exec 导入

<details>
<summary>答案与解析</summary>

**答案：B**。推荐绝对导入(from myapp.utils import x),清晰可读;少用相对/星号。
</details>

### 测验 4
让「直接运行才执行」的代码只在此场景跑,用?
- A. try/finally
- B. __name__ == "__main__"(正确)
- C. assert 判断
- D. logging 把关

<details>
<summary>答案与解析</summary>

**答案：B**。if __name__=="__main__": 保证被 import 时不执行,只有直接运行时跑。
</details>
